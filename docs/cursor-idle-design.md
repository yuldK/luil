# 커서 감추기와 멈춘 커서 자동 감추기

전체 화면 영상·그림 보기는 포인터가 멈추면 커서를 감추고, 움직이면 되돌린다. 앱이 창 메시지(`WM_SETCURSOR`)를 가로채 `SetCursor(nullptr)`를 부르지 않아도 되도록 두 가지를 둔다.

- `ui_cursor::none` — 이 element 위에서는 커서를 그리지 않는다.
- `ui_element::set_cursor_idle_hide(delay)` — 이 element 위에서 포인터가 `delay` 동안 움직이지 않으면 커서를 감춘다. 0이면 끈다.

공개 형식은 [ui_cursor.h](../include/luil/ui/ui_cursor.h)와 [ui_element.h](../include/luil/ui/ui_element.h)다.

## 언제 감추고 언제 되돌리는가

| 일 | 결과 |
| --- | --- |
| 정책이 있는 자리에서 `delay` 동안 움직임이 없다 | 감춘다 |
| 포인터가 움직였다 · 눌렀다 · 뗐다 | 곧바로 되돌리고 시계를 다시 잰다 |
| 포인터가 창을 떠났다 | 되돌린다 (창 밖의 커서는 OS의 것이다) |
| 창이 초점을 잃었다 | 되돌린다 |
| 새 tree에서 그 자리의 정책이 빠졌다 | 되돌린다 |
| 새 tree에서 그 자리에 정책이 새로 섰다 | 시계를 그때부터 잰다 — 오래 멈춰 있던 포인터 아래 보기가 서는 순간 커서가 사라지지 않는다 |
| 버튼을 누른 채 멈췄다 (끌기를 붙잡고 있다) | 감추지 않는다 |
| 표면이 사라졌다 | 화살표로 되돌려 둔다 (감춘 커서는 스레드의 커서라 창보다 오래 남는다) |

- **정책은 포인터 아래 element가 그 element 안에 있을 때만 선다**(`ui_tree::cursor_idle_hide_at`). 보기 위를 덮은 도구 막대·대화 상자 위에서는 감추지 않는다. 그 자리의 주인은 덮은 쪽이다. 아무도 hit를 받지 않는 자리(그림만 있는 보기)는 정책의 자리다.
- 여럿이 겹치면 가장 안쪽(나중에 담은) 것의 시간이 정한다. 숨긴 element, 잘려 보이지 않는 자리는 정책이 없다.
- 같은 자리의 이동 메시지는 움직임이 아니다. 창이 움직이거나 덮개가 걷히면 OS가 같은 자리의 `WM_MOUSEMOVE`를 다시 보낸다.

## 왜 시간을 표면이 재는가

멈춘 시간을 상호작용 발행본(`interaction_snapshot`)에 실으면 포인터가 움직일 때마다 발행본이 바뀌고, 발행본이 바뀌면 모든 창이 다시 그려진다. 감춤은 그림이 아니라 커서 모양이라 그 창 혼자 알면 된다. 그래서 Win32 표면이 포인터 메시지마다 장부(`cursor_idle_tracker`)를 갱신하고, 기한 timer에 다시 묻는다. tree는 그 자리에 정책이 있는지만 답한다.

감춘 동안 다른 길(끌기가 끝남, tree 교체)이 모양을 다시 걸어도 감춘 그대로다. 되돌리는 것은 위 표의 계기뿐이다.

## Android

포인터 커서가 없는 플랫폼이라 두 설정 모두 아무 뜻이 없다. 마우스를 붙인 Android의 커서 모양은 지금 luil이 다루지 않는다.

## 검증

- `tests/cursor_idle_tests.cpp`: 시간 경과로 감춤, 이동으로 되돌림, 떠남·초점 상실·정책 상실의 되돌림, 정책이 새로 선 때의 시계, tree가 정책을 답하는 자리(덮은 도구 막대·숨긴 element·표면 밖).
- 데모 "확대 보기" 페이지의 도면 위에서 포인터가 1.5초 멈추면 커서가 숨는다.
