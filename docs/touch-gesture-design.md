# 터치 제스처와 펜 입력 설계

이 문서는 Win32 입력의 장치 종류를 보존하고, 터치에만 끌어 스크롤하기와 길게 누르기를
적용하는 구현안이다. 현재 변경사항의 구현 완료를 뜻하지 않는다. 마우스와 키보드는 기존
동작을 유지하고, 펜은 클릭·우클릭·선택·드래그·호버를 제공한다.

원격 프로그램이 터치를 마우스 메시지로 변환해 전달하면 마우스로 취급한다. 입력 종류를
추측하거나 마우스에 터치 제스처를 켜는 옵션은 제공하지 않는다. 원격에서도 PT_TOUCH로
도착한 입력만 터치 제스처 대상이다.

## 입력 종류별 동작

| 입력 | 기본 누름 | 이동 | 컨텍스트 메뉴 | 호버 |
| --- | --- | --- | --- | --- |
| 마우스 | 기존 좌클릭과 더블 클릭 | 기존 선택·드래그·손잡이 조작 | 우클릭 | 기존 커서·툴팁 |
| 키보드 | 기존 초점 컨트롤 실행 | 기존 초점 이동·값 조절 | 기존 앱 키 정책 | 해당 없음 |
| 터치 | 짧은 탭은 클릭, 연속 탭은 기존 더블 클릭 계약 | 축에 맞는 빠른 스와이프는 스크롤 | 움직이지 않고 오래 눌렀다 떼면 우클릭 | 접촉 종료 뒤 hover를 남기지 않음 |
| 펜 | 펜촉 접촉은 좌클릭, 연속 접촉은 더블 클릭 | 텍스트 선택·드래그·손잡이 조작 | 배럴 버튼을 누른 접촉은 우클릭 | 비접촉 이동으로 커서·툴팁 갱신 |

펜을 오래 누르거나 쓸어도 라이브러리의 터치 제스처는 실행하지 않는다. 일반 컨트롤에는
필압·기울기로 별도 액션을 부여하지 않는다. 지우개 끝도 일반 버튼의 삭제나 우클릭으로
임의 변환하지 않으며, 일반 컨트롤을 실행하지 않는다. 잉크 편집은 후속 기능의 범위다.
웹뷰에는 펜 종류·버튼·지우개 등 원래 정보를 전달해 웹 콘텐츠가 자체 동작을 결정한다.

## Win32 메시지 수신

마우스는 현재 WM_MOUSEMOVE와 버튼·휠 메시지 경로를 사용한다. 터치·펜은
WM_POINTERDOWN, WM_POINTERUPDATE, WM_POINTERUP, WM_POINTERENTER,
WM_POINTERLEAVE, WM_POINTERCAPTURECHANGED를 공통 window_surface에서 처리한다.
주 창·popup·보조 창에 같은 규칙을 적용한다. 비클라이언트 영역은 기존 창 chrome과 OS의
창 이동·크기 조절 경로가 담당한다.

UI 스레드가 메시지를 받는 즉시 GetPointerType과 GetPointerInfo를 조회한다. 필요한
터치·펜 상세 정보도 이때 조회하고 값을 복사한다. 입력 스레드에 포인터 ID만 보내고 나중에
Win32를 조회하는 구조는 사용하지 않는다. 해당 정보는 메시지를 받은 스레드와 현재
메시지에 종속되기 때문이다. [GetPointerInfo 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerinfo)

WM_POINTER 좌표는 화면의 물리 픽셀이므로 수신한 표면의 client 좌표로 변환한다.
공개 UI 이벤트의 좌표 계약은 유지한다. 터치 판정 거리는 누름 표면의 DPI 배율로 나눈
논리 픽셀로 측정하고, 누른 동안에는 그 기준 배율을 고정한다. 입력 시각도 OS 메시지의
시각을 공통 단조 시계 기준으로 변환한다. 메시지 큐의 지연을 접촉 시간으로 오인하지 않도록
변환 계층의 시각 주입을 테스트할 수 있게 한다.

터치·펜 접촉은 포인터별 암묵적 캡처를 사용한다. 현재 마우스의 SetCapture와
ReleaseCapture를 터치·펜에 그대로 적용하지 않는다. 캡처 상실이나
POINTER_FLAG_CANCELED는 정상적인 뗌과 구별해 취소 이벤트를 만든다.
[포인터 메시지 문서](https://learn.microsoft.com/en-us/windows/win32/inputmsg/wm-pointerdown)

처리하기로 한 포인터 시퀀스는 처음부터 끝까지 같은 경로로 소비한다. 일부 이동만
DefWindowProc에 넘겨 OS 제스처·마우스 변환을 섞지 않는다. 조회 실패가 접촉 도중
발생하면 해당 접촉을 취소하고 남은 시퀀스를 소비한다. 처음부터 지원하지 않는 종류는
기본 처리에 맡긴다. [캡처 상실 문서](https://learn.microsoft.com/en-us/windows/win32/inputmsg/wm-pointercapturechanged)

EnableMouseInPointer로 프로세스 전체의 마우스 경로를 바꾸지 않는다. 직접 소비한
터치·펜 시퀀스를 마우스 호환 메시지로 재실행하지 않으며, 남는 합성 메시지가 있는지는
실기기에서 확인한다. 출처 식별로 중복만 제거하고 정상 마우스 입력은 유지한다.

## 내부 이벤트와 접촉 소유권

ui_events.h의 이동·누름·뗌·이탈 이벤트에 공통 포인터 정보를 추가한다.
제안하는 최소 정보는 pointer_device { mouse, touch, pen }, pointer_id, in_contact,
누름 표면의 배율이다. 기존 이벤트의 기본 장치 종류는 mouse이고 새 필드는 뒤에 두어
기존 aggregate 초기화와 테스트의 의미를 보존한다. Win32 구조체·핸들은 공개 이벤트에
넣지 않는다.

pointer_cancelled_event를 추가한다. 취소는 클릭·우클릭·drop을 실행하지 않는 상태
정리다. 포인터 키는 장치 종류·ID·시작 표면의 조합이며, 누름이 스크롤로 바뀌어도 접촉
소유권은 유지한다. clear_press()가 이 소유권까지 지우도록 만들지 않는다.

현재 controller는 활성 조작 하나만 처리하므로 luil UI의 최초 구현도 한 접촉으로 한 조작을 한다.
추가 손가락은 어댑터에서 시퀀스를 추적하되 컨트롤 액션을 실행하지 않는다. 첫 손가락을
뗐다고 아직 내려가 있는 두 번째 손가락을 새 누름으로 승격하지 않는다. ID가 다른
이동·뗌·취소는 활성 조작을 바꾸지 않는다. 실제 마우스나 펜의 새 누름은 진행 중 터치
조작을 취소한 뒤 새 조작을 시작하며, 취소된 터치의 나머지 이벤트는 소비한다.
웹뷰에서 시작한 접촉들은 별도로 중계하며 웹뷰의 다중 접촉 동작을 이 제한으로 막지 않는다.

더블 클릭의 연속성은 대상·표면·장치 종류로 구분한다. 접촉마다 달라질 수 있는 터치
포인터 ID를 연속 탭의 동일성 조건으로 삼지 않는다. 마우스 클릭과 터치 탭, 펜 접촉을
서로 합쳐 더블 클릭으로 처리하지 않는다.

## 터치 판정과 드래그 우선순위

터치 상태는 대기, 스크롤, 일반 드래그, 전용 손잡이 조작, 취소로 구분한다.
누름 시 클릭 대상과 스크롤 후보를 별도로 찾는다. hit_test에 클릭 대상이 없어도
스크롤 영역의 여백·일반 텍스트 위에서 후보를 만들 수 있다. 비활성 요소와
hit_opaque 방벽을 통과해 뒤의 후보를 잡지는 않는다.

대기 상태에서는 시작점과의 거리 및 최대 이동 거리를 갱신한다. 첫 이동 이벤트가
8픽셀인지 20픽셀인지에 따라 드래그와 스크롤 결과가 바뀌지 않아야 한다.

1. 스크롤 후보가 있고 시간 창 안에 축 방향의 스크롤 임계를 넘으면 스크롤을 시작한다.
2. 시간 창 안에서 스크롤 임계에 못 미치면 일반 드래그 확정을 보류한다.
3. 임계를 넘었지만 축이 다르거나 시간 창이 지났으면 스크롤 후보를 종료한다.
   drag_source가 있으면 터치용 이동 임계를 확인해 일반 드래그를 시작한다.
4. pointer_drag_target은 누르는 즉시 전용 조작을 시작한다. 이 대상은 스크롤 후보가
   아니다. 실제 이동 액션이 발행된 뒤에는 길게 누르기로 메뉴를 열지 않는다.

터치용 드래그는 마우스의 기존 6픽셀 임계를 그대로 적용하지 않는다. 터치의 움직임
허용치로 판정한다. 마우스·펜의 기존 드래그 임계와 이벤트 경로는 별도로 유지한다.

텍스트 칸에서는 터치 탭으로 caret을 놓되, caret 배치 액션은 탭이 확정된 뗌에 실행한다.
부모 스크롤 영역이 있는 칸을 빠르게 쓸면 부모가 스크롤한다. 마우스·펜의 누른 채 범위
선택은 현재 동작을 유지한다. 터치 선택 손잡이와 낱말 선택 메뉴는 이 구현의 범위에
추가하지 않는다. 텍스트 칸에 우클릭 액션이 있으면 터치 길게 누르기로 실행할 수 있다.

길게 누르기는 대기 상태에서만 가능하다. 접촉 중 한 번이라도 최대 이동 허용치를 넘으면
끝까지 자격을 잃는다. 원위치로 돌아와도 복원하지 않는다. 현재 이벤트 중심 구조에 맞춰
기본 600ms 이상 누른 뒤 정상적으로 뗄 때 우클릭 액션을 실행한다. 누르고 있는 동안
메뉴를 여는 타이머 동작은 이번 구현에 포함하지 않는다.

길게 누르기 대상에 우클릭 액션이 없으면 이동하지 않은 탭으로 처리한다. 우클릭을
실행했다면 클릭·더블 클릭을 함께 실행하지 않고 연속 탭 기록도 거둔다. 이동 허용치를
넘었지만 스크롤이나 드래그가 되지 않은 접촉은 클릭으로 되돌리지 않는다.

## 스크롤 대상과 범용 컨테이너

스크롤 후보는 소유자 ID, 시작 표면, 축, 배율, 스크롤 메시지 factory를 가진다.
표 없는 경로는 현재 scroll_source를 사용한다. 안쪽·위쪽 후보를 먼저 찾고
hit_opaque를 방벽으로 삼는 규칙은 공통 탐색 함수로 유지한다.

가로 strip_element와 tab_bar_element의 config에 스크롤 factory를 전달할 수 있게
한다. arrange 이후 넘침이 있을 때 소유자와 가로 축·배율을 등록한다. 데모의 탭 막대와
네트워크 가로 띠도 이 경로로 연결한다. 휠·초점 reveal에서 쓰던 factory를 재사용한다.

기존 휠 라우팅 표의 API는 유지한다. 사용자 정의 표만으로 동작하는 컨테이너에는
interaction_policy::pan_target_at(tree, x, y) 확장 지점을 제안한다. 기본 구현은
scroll_source 탐색이며, 표용 보조 함수는 소유자 ID와 factory에 명시적인 축·배율을
더해 같은 후보를 만든다. 표용 탐색도 가시성·활성·clip·방벽 규칙을 지켜야 한다.
축과 배율을 알 수 없는 휠 표를 임의로 세로·배율 1로 추측하지 않는다.

스크롤 시마다 새 tree에서 대상과 조상 경로의 가시성·활성 및 유효한 factory를
재확인한다. 표용 policy도 새 tree에서 누른 자리의 후보를 다시 해석하고, 기존 소유자 ID와
축이 유지되는 경우에만 최신 factory를 사용한다. 사라지거나 비활성화되었으면 취소하며,
새 modal이 기존 접촉 경로를 가로막아도
취소한다. 취소된 접촉의 뗌은 클릭이 되지 않는다.

각 델타는 이전 물리 위치와 현재 위치의 축 방향 차이를 그 컨테이너의 배율로 나눈다.
스크롤 시작 시에는 누른 위치부터 누적된 이동을 반영하고, 정상적인 뗌의 마지막 좌표
변화도 반영한다. 스크롤 경계에서 대상이 사라졌다고 뒤쪽 컨테이너로 갑자기 전환하지
않는다. 중첩 축은 가장 안쪽 후보를 기준으로 잠그며, 축이 다르면 이번 접촉의 스크롤을
시작하지 않는다. 바깥 축으로 넘기는 동작·관성·핀치·회전은 후속 범위다.

## 펜 버튼과 접촉 수명

펜의 호버는 누름 없이 hover와 커서를 갱신한다. 접촉은 첫 번째 버튼을 좌클릭,
두 번째 버튼을 우클릭에 대응시킨다. 접촉 중 배럴 버튼이 바뀌면 이전 버튼의 대기 누름을
취소한 뒤 새 버튼 상태로 전환한다. 좌클릭과 우클릭을 모두 실행하지 않는다. 진행 중
드래그를 버튼 전환으로 취소해도 drop 액션을 실행하지 않는다.

펜의 캡처 상실·취소는 터치와 동일한 명시적 취소 경로를 사용한다. 비접촉 이탈은 hover를
거두지만, 단순한 경계 통과를 접촉 해제로 오인하지 않는다. 터치도 창 밖으로 이동했다고
정상 뗌으로 합성하지 않는다.

## 웹뷰 전달

현재 webview_host는 SendMouseInput만 사용하므로 네이티브 포인터 중계를 추가한다.
UI 스레드에서 복사한 정보를 ICoreWebView2PointerInfo로 옮기고 웹뷰 좌표로 변환해
SendPointerInput에 전달한다. 터치·펜 상세 정보를 일반 컨트롤 이벤트로 축소하기 전에
웹뷰에 필요한 데이터를 확보한다. [WebView2 포인터 입력 문서](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2compositioncontroller?view=webview2-1.0.4191.47)

접촉이 시작될 때 웹뷰 또는 luil UI 중 한 소유자를 선택한다. 접촉이 영역 밖으로 나가도
소유자를 유지하며, 웹뷰에서 시작한 시퀀스를 뒤의 목록 제스처로 넘기지 않는다. 감춤·제거·
캡처 상실 때도 소유자에게 취소를 전달하고 ID별 중계 상태를 정리한다. 중계 실패 역시
뒤쪽 UI에서 새 누름을 합성하는 이유가 되지 않는다. 마우스는 기존 중계를 유지한다.

## 런타임 설정

제안하는 공개 설정은 touch_gesture_config이며, interaction_config::touch와
window_config::touch에 둔다. 실제 선언은 구현 단계에서 확정한다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| pan_enabled | true | 네이티브 터치 스크롤 활성화 |
| long_press_enabled | true | 네이티브 터치 길게 누르기 활성화 |
| pan_start_distance | 12 논리 픽셀 | 스크롤 시작 거리 |
| pan_start_time | 400ms | 빠른 스크롤과 오래 잡은 드래그를 구분하는 시간 창 |
| press_move_tolerance | 12 논리 픽셀 | 탭·길게 누르기의 최대 이동 허용치 및 터치 일반 드래그 시작 거리 |
| long_press_time | 600ms | 길게 누르기 시간 |

거리·시간이 0이면 끈다는 중의적인 계약을 제거하고 활성화 bool로 제어한다. 거리는
유한한 양수, 시간은 양수이며, pan_start_time < long_press_time을 검증한다.
잘못된 설정은 갱신 실패로 알리고 직전 설정을 유지한다. 시작 설정은 창 시작 실패로
알린다. 마우스·키보드·펜에 제스처를 허용하는 설정은 없다.

초기값은 window_config → app_host::config → interaction_controller로 전달한다.
실행 중 변경은 app_host::set_touch_gesture_config가 최신 값 slot에 게시하고, 입력
스레드가 다음 이벤트 처리 전이나 기존 receive timeout에서 적용한다. 게시 성공은 적용
완료와 구별한다. 구성 변경은 접수된 입력 큐의 사건 순서와 원자적으로 묶인다는 계약을
제공하지 않으며, 최신 설정을 입력 스레드가 읽은 시점부터 적용한다.

진행 중 접촉의 거리·시간 값은 누를 때의 값을 사용한다. 관련 활성화 bool을 끄면 해당
대기·스크롤을 취소하고 남은 뗌을 소비한다. 비활성화 직후 스크롤이 클릭으로 바뀌거나
다시 켰을 때 내려가 있는 손가락이 새 접촉으로 시작되지 않는다. 설정이 바뀌어도 마우스·
펜 조작과 웹뷰 자체의 터치 동작은 바뀌지 않는다.

## 기존 policy와 액션 계약

interaction_policy::on_press는 누름 관찰 hook으로 유지한다. 장치 정보가 있는 이벤트를
받지만 그 자체로 제스처 판정을 대신하지 않는다. 클릭 대상이 없는 스크롤 여백에서
가짜 클릭 대상을 만들어 hook을 호출하지 않는다. 앱은 누름에서 화면이 바뀔 수 있음을
고려하고, 이후 제스처는 다음 tree에서 소유자를 재검증한다.

터치 우클릭·펜 우클릭도 같은 액션 실행 경로를 사용한다. 대상의 활성 상태 검사와
on_click 같은 기존 정책 알림을 경로마다 빠뜨리지 않는다. 스크롤로 확정된 접촉은
클릭 정책 알림을 실행하지 않는다.

## 구현 순서와 검증

1. 공통 포인터 정보·취소 이벤트와 Win32 변환을 추가한다. 기존 이벤트를 장치 기본값이
   mouse인 채 처리했을 때 기존 테스트 결과가 같아야 한다.
2. 장치별 분기와 접촉 소유권을 넣고 펜 클릭·우클릭·호버·텍스트 선택을 연결한다.
3. 터치 상태 기계와 최대 이동 기록을 넣고 스크롤 컨테이너·표용 경로를 연결한다.
4. 웹뷰 포인터 중계와 공개 런타임 설정을 연결한다.
5. 아래 회귀 테스트와 실기기 검증 후 코드 주석·공개 API 문서를 최종 계약으로 맞춘다.

| 검증 대상 | 통과 조건 |
| --- | --- |
| 장치 구분 | 동일 좌표·시각의 mouse·pen은 제스처가 없고 touch만 스크롤·길게 누르기 실행 |
| 마우스·키보드 | 기존 클릭·더블 클릭·드래그·휠·키 라우팅 테스트 유지 |
| 펜 | 좌클릭·배럴 우클릭·버튼 전환·호버·선택·취소·지우개가 계약대로 동작 |
| 연속 탭 | 서로 다른 터치 ID의 연속 탭은 가능하고 다른 장치의 클릭과 섞이지 않음 |
| 이동 이벤트 빈도 | 같은 스와이프를 8→20픽셀과 20픽셀 한 번으로 입력해 같은 스크롤 판정 |
| 빈 곳·텍스트 | 클릭 액션 없는 영역에서 스크롤 가능, 텍스트 탭만 caret을 배치 |
| 이동 이력 | 멀리 이동했다 돌아온 접촉·실제 손잡이 조작은 길게 누르기 불가 |
| 라우팅 | 세로·가로·사용자 정의 표·clip·modal 방벽·중첩 축의 계약 검증 |
| tree 변경 | 소유자 삭제·숨김·비활성·modal 등장·표면 삭제에서 액션 없이 취소 |
| 접촉 수명 | 다른 ID의 뗌·추가 손가락·새 장치 누름·입력 큐 유실에서 잘못된 클릭·drop 없음 |
| 좌표·시각 | 100%·150%·200% DPI, 음수 화면 좌표, 큐 지연, 시각 wrap 변환 검증 |
| 런타임 설정 | 초기 전달·잘못된 값 거절·진행 중 비활성화·재활성화 검증 |
| 웹뷰 | 시작 소유권·영역 밖 이동·취소·감춤·중계 실패·중복 액션 방지 검증 |

순수 변환·controller 테스트에 더해 실제 터치 화면과 펜에서 Win32 수신 메시지 종류,
OS 호환 메시지 중복, 캡처 상실, 웹뷰 전달을 확인한다. 원격 환경은 터치 종류가
보존되는 연결과 마우스로 변환되는 연결을 구분해 검증한다. 현재 테스트 실행 파일의
통과만으로 네이티브 입력 지원 완료를 판정하지 않는다.
