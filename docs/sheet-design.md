# 시트와 서랍

`sheet_host_element`는 같은 표면 안에서 화면 위에 겹치는 아래 시트, 오른쪽 옆 시트, 왼쪽 탐색 서랍이다. 공개 API는
[sheet_host_element.h](../include/luil/ui/sheet_host_element.h)에 있다.

## popup과 다른 점

Android host에서 popup(`ui_popup`)은 뒤로 가기·바깥 누름·Esc·표면 크기 변경(`surface_resized`)으로 닫힌다. 메뉴·드롭다운에는
맞는 계약이고 바꾸지 않는다. 시트는 화면의 일부라서 회전하거나 화면 분할로 크기가 바뀌어도 남아야 하고, 넓어지면 아래 시트가
옆 시트로 바뀌는 것이 관례다. 그래서 별도 표면이 아니라 **같은 tree 안의 overlay 요소**다 — [modal dialog host](modal-dialog-design.md)와
같은 자리다.

- **상태는 앱의 것이다.** 열림(tree에 담는가), 멈춤점(`detent`), 끄는 중인 양(`drag_offset`), 시트 안 목록의 스크롤이 전부
  앱 상태이고, host는 매 frame 받은 값으로 그 frame의 자리에 배치한다. 회전·화면 분할·창 크기 변경 뒤에 다시 지은 tree도 같은
  값을 받으므로 열림·멈춤점·스크롤이 그대로 남는다.
- **회전은 닫힘 계기가 아니다.** 닫힘 계기(`sheet_dismiss_reason`)는 scrim 누름, 뒤로 가기, Esc, 아래로 끌어 놓기 넷이고
  `dismiss` 메시지로 앱에 알린다. 닫는 것은 앱이 tree에서 빼는 것이다.
- Windows에서도 같은 요소다. 창 크기를 바꾸면 같은 규칙으로 다시 배치되고, 마우스로 손잡이를 끌고, modal이면 Esc로 닫는다.

## 종류와 배치

| 종류 | 자리 | 크기 |
| --- | --- | --- |
| `bottom` | 아래에 붙는다. 넓은 자리에서는 가운데 | 폭은 `bottom_max_width`(640)까지, 높이는 멈춤점에서 끄는 양을 뺀 것 |
| `end` | 오른쪽 가장자리, 전체 높이 | `side_width`(360). 자리가 좁으면 왼쪽에 56을 남기고 줄인다 |
| `start` | 왼쪽 가장자리, 전체 높이 | `end`와 같고 오른쪽에 56을 남긴다 |

아래 시트의 멈춤점은 둘이다. 반(`half`)은 자리 높이의 반, 전체(`full`)는 위에 `full_top_margin`(24)을 남긴 높이다. 보이는 높이는
멈춤점 높이에서 `drag_offset`을 빼고 0과 전체 높이 사이로 다듬는다 (`sheet_visible_height`). 바탕은 화면 안쪽을 향한 모서리만
둥글고, 그림자는 host 자리 안에만 드리운다 (화면 가장자리 너머로 비치지 않게).

**적응형.** `side_from_width`를 주면 아래 시트가 폭이 그 값(논리 픽셀) 이상인 자리에서 오른쪽 옆 시트로 선다
(`resolve_sheet_kind`). 기준 폭은 인자다 — [창 폭 등급](device-request-design.md#창-폭-등급)의 medium 경계(600)를 주면 휴대폰
가로·펼친 접는 기기·태블릿에서 옆 시트가 된다. 멈춤점은 앱 상태라 옆 시트로 갔다 돌아와도 그대로다.
끌기 도중 옆 시트로 바뀌면 앱은 임시 `drag_offset`을 0으로 거둔다. 옆 시트에는 끌기 종료 콜백이 없으며,
mobile demo는 이 전환에서 멈춤점과 목록 위치를 유지하고 끄는 양만 버린다.

## 안전 영역 밖

앱이 배치 문맥에 `surface`(그릴 수 있는 표면 전체, `window_surface`)를 넘기면 화면 끝까지 칠한다
([기기 요청](device-request-design.md#안전-영역-밖)).

- modal이면 scrim 색을 자리 밖의 띠까지 칠한다 (상태 표시줄·제스처 막대·컷아웃 자리).
- 시트 바탕은 자리 가장자리에 닿은 변만 표면 끝까지 늘린다 (`sheet_background_bounds`). 아래 시트는 아래(폭이 꽉 차면 좌우도),
  옆 시트는 위·아래·오른쪽, 서랍은 위·아래·왼쪽이다. 넓은 자리의 가운데 아래 시트는 아래만 늘린다.
- 손잡이·내용·누르는 자리와 멈춤점 높이는 그대로 안전 영역 안이다. 그림자도 표면 안으로 자른다.
- 넘기지 않으면 지금과 같다 — 자리 안에만 그리고 그림자는 host 자리로 자른다.

## 끌기

아래 시트만 끈다. 옆 시트와 서랍은 scrim·뒤로 가기·Esc로 닫고, 가장자리에서 끌어 서랍을 여는 몸짓은 두지 않았다 (요청에서 선택이었다).

- **손잡이.** 시트 위 24 논리 픽셀의 띠가 `pointer_drag_target`이다. 터치·펜·마우스 모두 누르는 즉시 끌기이고, 끈 만큼 `drag`
  메시지(논리 픽셀, 아래가 양수)가 나간다. 앱은 `drag_offset`에 더한다.
- **놓기.** 손을 떼면 host가 닫힘(0)·반·전체 중 멈출 자리를 고른다 (`settle_sheet`). 닫힘으로 정해지면 `dismiss(drag)`,
  아니면 `settle(멈춤점)`이 나간다. 앱은 멈춤점을 넣고 `drag_offset`을 0으로 되돌린다.
  - 놓은 순간의 속도가 `fling_velocity`(초당 300 논리 픽셀) 이상이면 **튕김**이다. 지금 보이는 높이에서 그 방향의 다음
    자리로 간다 — 아래로 튕기면 지금보다 낮은 첫 자리(없으면 닫힘), 위로 튕기면 높은 첫 자리(없으면 전체)다. 전체에서
    아래로 튕기면 반, 반에서 아래로 튕기면 닫힘, 반에서 위로 튕기면 전체다. 0 이하로 두면 속도를 보지 않는다.
  - 튕김이 아니면 지금 보이는 높이와 가장 가까운 자리다.
  - 높이가 아니라 방향으로 정하므로, 앱이 끈 양을 아직 tree에 싣지 않아 멈춤점 높이 그대로 보여도 한 칸은 옮긴다.
  - 속도는 놓기 전 100ms 동안의 이동으로 잰다 (`drag_velocity`, [확대 보기의 경계 쓸기](zoom-view-design.md)와 같은 창).
    그 사이 이동이 둘보다 적으면 0이라, 끌다 멈추고 놓거나 손잡이를 누르는 동안 손가락이 조금 흔들린 것은 튕김이 아니다.
    놓은 자리는 넣지 않는다 — 마우스는 capture를 잃으면 화면 밖 자리의 합성 뗌으로 끝난다.
- **뗌 없이 끝난 끌기.** 시스템이 터치·펜 접촉을 거두거나, 입력 큐가 넘쳐 진행 중인 몸짓을 통째로 거둘 때
  (`interaction_controller::cancel_dropped_gestures`)도 놓기와 같이 멈춤점을 정한다. 끄던 시트가 그 자리에 남지 않는다.
  끝을 모르므로 속도는 0이다 (가장 가까운 자리).
- **시트 몸의 터치 끌기.** 시트 바탕은 `pan_handoff_target`이다. 터치가 세로로 흐르기 시작하는 순간(축 판정,
  [터치 몸짓](touch-pen-input-design.md#터치-판정과-드래그-우선순위)과 같은 시간 창과 시작 거리) 한 번 정한다.
  - 누른 자리에 시트 안의 세로 흘리는 창이 없으면 시트가 받는다 (짧은 시트는 위아래로 끈다).
  - 있으면, 그 창이 맨 위(`scroll_source::at_start`)이고 손가락이 아래로 움직일 때만 시트가 받는다. 그 밖에는 지금처럼 창이
    흐른다. 접촉 도중 창이 맨 위에 닿아도 넘기지 않는다 — 넘기는 순간이 하나여야 손가락 아래의 동작이 바뀌지 않는다.
  - `at_start`는 앱이 싣는다. 위치를 앱이 들고 있어서다. 기본은 거짓이라 지금까지의 흘리는 창은 넘기지 않는다.
  - 마우스·펜으로 시트 몸을 끄는 것은 몸짓이 아니다. 손잡이를 쓴다.
  - 뗌의 마지막 이동도 `drag`로 내고, `release(final_delta, velocity)`에 함께 넘긴다. 이 이동은 아직 tree에
    실리지 않았으므로 host는 받은 `drag_offset`에 더해 최종 멈춤점을 고른다. 취소·입력 유실의 `final_delta`는 0이다.
- **손잡이는 손가락을 따라간다.** 시트가 내려가면 누른 자리는 곧 scrim에 덮인다. 기존 터치 손잡이는 누른 자리를 다른 것이 덮으면
  끌기를 끊는데, 시트 손잡이(`follows_pointer`)와 넘겨받은 시트 바탕은 누른 자리의 hit이 아니라 id·가시성·가둠으로 살아 있는지 본다.
  새 modal이 뜨면 가둠 밖이 되어 끊긴다. 터치·펜·마우스 모두 숨김·비활성·가둠 밖 손잡이에 이동이나 종료 콜백을 보내지 않는다.

## modal과 비modal

| | modal (기본) | 비modal |
| --- | --- | --- |
| 뒤 화면 | scrim이 덮고 포인터를 막는다. 누르면 `dismiss(scrim)` | 그대로 쓸 수 있다 |
| 초점 | 가둔다 (`focus_entry`·`focus_return`은 modal dialog와 같다) | 가두지 않는다 |
| Esc | `dismiss(escape)` | 앱의 키 정책으로 흐른다 |
| 보조 기술 역할 | dialog | pane |

**뒤로 가기는 앱이 잇는다.** 뒤로 가기는 플랫폼의 계기라 host가 아니라 frame의 `ui_frame::back`이 받는다 (modal dialog와 같은
방식). 시트가 열려 있는 동안 앱이 `back`에 `dismiss(sheet_dismiss_reason::back)`과 같은 메시지를 싣는다. mobile demo의 시트
페이지가 그렇게 한다.

## 남은 것

- 서랍을 가장자리에서 끌어 여는 몸짓이 없다. 제스처 탐색에서는 왼쪽 가장자리 쓸기가 시스템의 뒤로 가기다.

## 검증

순수·controller test는 [sheet_host_element_tests.cpp](../tests/sheet_host_element_tests.cpp)에 있다.

| 대상 | 확인 |
| --- | --- |
| 멈춤점 | 반·전체 높이, 끄는 양의 다듬기, 아래 붙기와 최대 폭 가운데 |
| 놓기 | 가장 가까운 멈춤점, 반 높이의 반보다 내리면 닫힘, 같은 거리는 닫지 않음 |
| 튕김 | 방향의 다음 자리(전체→반, 반→닫힘, 반→전체), 반 위·아래에서 반으로, 느린 놓기는 가장 가까운 자리, 기준 0과 값이 아닌 속도는 무시, 손잡이·시트 몸·마우스 튕김, 멈췄다 놓기·흔들림·화면 밖 합성 뗌·취소는 튕김이 아님 |
| 끌어 닫기 | 터치 손잡이를 끌다 앱이 다시 지은 tree에서도 이어 끌고, 놓으면 `dismiss(drag)`. 마우스 손잡이는 놓으면 `settle` |
| 뗌 없는 끝 | 입력 큐 유실 뒤 터치 손잡이·넘겨받은 몸·마우스 손잡이가 멈춤점을 정하고 늦은 뗌은 아무것도 내지 않음, 펜 취소, 다른 표면의 손잡이 |
| 크기 변경 | 세로·가로·세로를 오가도 멈춤점이 남고, 넓은 자리에서 옆 시트, 좁은 자리에서 아래 시트 |
| 옆 시트·서랍 | 가장자리 자리, 좁은 자리의 56 남기기 |
| 안전 영역 밖 | 종류별로 늘린 바탕 자리, 표면을 알아도 같은 시트 자리, 자리 밖 누르기는 scrim이 받지 않음, scrim 띠와 늘린 바탕의 픽셀 (raster) |
| 초점 | modal의 가둠·dialog 역할·scrim·Esc, 비modal의 뒤 화면 |
| 넘겨받기 | 맨 위 목록의 아래 쓸기는 시트, 위 쓸기와 맨 위가 아닌 목록은 목록, 접촉 도중에는 넘기지 않음, 목록 없는 시트, 취소 뒤 멈춤점, 마우스 제외 |

기기 확인은 [Android 이식 계획](android-port-plan.md)의 "시트" 절에 있다.
