# 터치 제스처와 펜 입력

Win32 입력의 장치 종류를 보존하고, 터치에만 끌어 스크롤하기와 길게 누르기를 적용한다.
마우스와 키보드는 기존 동작을 유지하고, 펜은 클릭·우클릭·선택·드래그·호버를 제공한다.

원격 프로그램이 터치를 마우스 메시지로 변환해 전달하면 마우스로 취급한다. 입력 종류를
추측하거나 마우스에 터치 제스처를 켜는 옵션은 제공하지 않는다. 원격에서도 `PT_TOUCH`로
도착한 입력만 터치 제스처 대상이다.

이 계약은 이전 시안(마우스 누름에 시간 창을 두어 스크롤과 길게 누르기를 붙이던 방식)을
대체한다. 그 시안에서 `interaction_policy::on_press` 누름 관찰 hook만 이어받았다.

## 입력 종류별 동작

| 입력 | 기본 누름 | 이동 | 컨텍스트 메뉴 | 호버 |
| --- | --- | --- | --- | --- |
| 마우스 | 기존 좌클릭과 더블 클릭 | 기존 선택·드래그·손잡이 조작 | 우클릭 | 기존 커서·툴팁 |
| 키보드 | 기존 초점 컨트롤 실행 | 기존 초점 이동·값 조절 | 기존 앱 키 정책 | 해당 없음 |
| 터치 | 짧은 탭은 클릭, 연속 탭은 더블 클릭 | 축에 맞는 빠른 쓸기는 스크롤, 오래 잡고 옮기면 끌기 | 움직이지 않고 오래 눌렀다 떼면 우클릭 | 남기지 않음 |
| 펜 | 펜촉 접촉은 좌클릭, 연속 접촉은 더블 클릭 | 텍스트 선택·드래그·손잡이 조작 | 배럴 버튼을 누른 접촉은 우클릭 | 비접촉 이동으로 커서·툴팁 갱신 |

펜을 오래 누르거나 쓸어도 터치 제스처는 실행하지 않는다. 일반 컨트롤에는 필압·기울기로
별도 액션을 부여하지 않는다. 지우개 끝의 접촉은 삼킨다. 삭제나 우클릭으로 임의 변환하지
않으며 일반 컨트롤을 실행하지 않는다. 잉크 편집은 후속 기능의 범위다. 웹뷰에는 펜
종류·버튼·지우개·필압 등 원래 정보를 그대로 전달해 웹 콘텐츠가 자체 동작을 결정한다.

## Win32 메시지 수신

마우스는 기존 `WM_MOUSEMOVE`와 버튼·휠 메시지 경로를 사용한다. 터치·펜은
`WM_POINTERDOWN`, `WM_POINTERUPDATE`, `WM_POINTERUP`, `WM_POINTERENTER`,
`WM_POINTERLEAVE`, `WM_POINTERCAPTURECHANGED`를 공통 `window_surface`에서 처리한다.
주 창·popup·보조 창이 같은 경로를 쓴다. 비클라이언트 영역(`WM_NCPOINTER*`)은 기존 창
chrome과 OS의 창 이동·크기 조절 경로가 담당한다.

UI 스레드는 메시지를 받는 즉시 `GetPointerType`과 `GetPointerTouchInfo` 또는
`GetPointerPenInfo`를 조회하고 값을 복사한다. 이 값은 메시지를 받은 스레드와 현재
메시지에 종속되므로 입력 스레드에 포인터 ID만 보내 나중에 조회하지 않는다.
[GetPointerInfo 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getpointerinfo)

복사한 값은 Win32 구조체를 담지 않는 `pointer_sample`로 옮기고,
`pointer_sequence_tracker`가 접촉별 상태를 들고 입력 이벤트로 바꾼다
([pointer_sequence.h](../src/host/pointer_sequence.h)). 메시지 종류는 플랫폼을 가리지 않는
접촉 단계(`pointer_phase`)로 옮겨 넣으므로 다른 플랫폼도 같은 추적기를 쓴다. 이 계층은 창도
시계도 모르므로 변환을 결정적으로 테스트할 수 있다.

- 좌표는 화면 물리 픽셀이라 수신한 표면의 client 좌표로 옮긴다. 공개 UI 이벤트의 좌표
  계약은 그대로다.
- 누름 이벤트에 표면의 배율(`dpi / 96`)을 싣는다. 터치 판정 거리는 이 배율로 나눈 논리
  픽셀이며, 누른 동안 그 배율을 고정한다.
- 시각은 `POINTER_INFO::PerformanceCount`가 있으면 성능 카운터로, 없으면 32비트 tick
  (`dwTime`)으로 공통 단조 시계(`steady_clock`)에 옮긴다. 메시지 큐에서 기다린 시간을
  접촉 시간으로 오인하지 않는다. tick은 부호 없는 뺄셈으로 한 바퀴 돈 경계를 넘는다.
  지금보다 뒤인 값은 지금으로 본다.

터치·펜 접촉은 포인터별 암묵적 캡처를 사용한다. 마우스의 `SetCapture`·`ReleaseCapture`를
적용하지 않는다. 캡처 상실과 `POINTER_FLAG_CANCELED`는 정상적인 뗌과 구별해
`pointer_cancelled_event`를 만든다.
[포인터 메시지 문서](https://learn.microsoft.com/en-us/windows/win32/inputmsg/wm-pointerdown)

처리하기로 한 포인터 시퀀스는 처음부터 끝까지 같은 경로로 소비한다. 일부 이동만
`DefWindowProc`에 넘겨 OS 제스처·마우스 변환을 섞지 않는다. 표면은 접촉의 DOWN에서
임자(luil UI 또는 웹뷰)를 정하고 UP까지 바꾸지 않는다. 조회가 접촉 도중 실패하면 그
접촉을 취소하고 남은 시퀀스를 삼킨다. 처음부터 읽을 수 없거나 지원하지 않는 종류(마우스·
터치패드)는 기본 처리에 맡긴다. 캡처 상실은 취소 뒤 기록을 지운다. 캡처가 넘어간 뒤로는
UP이 오지 않을 수 있기 때문이다.
[캡처 상실 문서](https://learn.microsoft.com/en-us/windows/win32/inputmsg/wm-pointercapturechanged)

`EnableMouseInPointer`로 프로세스 전체의 마우스 경로를 바꾸지 않는다. 소비한 시퀀스는
OS가 마우스 호환 메시지로 바꾸지 않는다. 그래도 남는 합성 메시지는 출처 표식
(`GetMessageExtraInfo`의 `MI_WP_SIGNATURE`)으로 식별해, 소비 중인 시퀀스가 있을 때만
버린다. 정상 마우스 입력과 기본 처리에 맡긴 시퀀스의 변환은 그대로 받는다.

터치·펜의 DOWN도 마우스 누름처럼 popup 밖 누름(`pointer_press_outside`)으로 popup을
닫는다. 펜 hover는 메시지를 소비하므로 마우스 변환이 없다. 커서는 그 경로에서 직접 맞춘다.

## 내부 이벤트와 접촉 소유권

[ui_events.h](../include/luil/ui/ui_events.h)의 이동·누름·뗌·이탈 이벤트에 장치 정보를
뒤에 붙였다. 앞 필드만 채운 기존 초기화가 그대로 마우스를 뜻한다.

| 필드 | 이벤트 | 뜻 |
| --- | --- | --- |
| `device` | 이동·누름·뗌·이탈 | `pointer_device { mouse, touch, pen }`, 기본 mouse |
| `pointer_id` | 이동·누름·뗌 | 접촉 하나의 수명 동안 안정적인 id, 마우스는 0 |
| `in_contact` | 이동 | 펜촉·손가락이 닿아 있는가 (펜 hover와 접촉을 가른다) |
| `scale` | 누름 | 누른 표면의 물리 / 논리 배율 |

`pointer_cancelled_event`는 클릭·우클릭·drop을 실행하지 않는 상태 정리다. 마우스는
기존처럼 화면 밖 합성 뗌으로 거두며 이 경로를 바꾸지 않았다.

컨트롤러는 활성 조작 하나만 처리한다. 보통 터치는 한 접촉이 한 조작을 하고,
같은 [확대 보기](zoom-view-design.md)에서 핀치할 때만 두 접촉이 한 조작을 나눠 갖는다. 접촉 소유권은
누름 상태와 따로 들고 `clear_press()`가 지우지 않는다. 누름이 스크롤로 바뀌어도 접촉은
남는다.

- 같은 확대 보기의 대기·이동 접촉에 합류한 둘째 손가락을 제외하면 추가 손가락은
  컨트롤 액션을 실행하지 않는다. 첫 손가락을 뗐다고 아직 내려가 있는
  손가락을 새 누름으로 승격하지 않는다. id가 다른 이동·뗌·취소는 활성 조작을 바꾸지 않는다.
- 실제 마우스나 펜의 새 누름은 진행 중인 터치 조작을 취소하고 시작한다. 취소된 터치의
  나머지 이벤트는 쥔 접촉이 없어 삼켜진다. 마우스·펜이 조작 중일 때의 터치 누름은 삼킨다.
- 터치가 조작을 쥔 동안의 마우스·펜 이동은 hover만 바꾸고 터치 조작을 움직이지 않는다.
- 마우스·펜 조작도 장치·포인터 id·표면·버튼으로 누름의 소유권을 유지한다. 다른 장치의
  hover나 늦은 뗌·취소가 선택·손잡이·drop을 바꾸지 않는다. 새 누름은 옛 조작을 취소하고
  시작한다. 펜 누름에는 Shift 상태도 전달해 마우스처럼 선택을 확장한다.
  합성 포인터가 `dwKeyStates`를 채우지 않는 경우도 있으므로 네이티브 수신 시
  메시지 큐에 동기화된 `GetKeyState`의 Shift·Ctrl 상태를 함께 복사한다. 현재 물리 키
  상태를 읽는 `GetAsyncKeyState`로 뒤에 온 키 변경을 섞지 않는다.
  같은 장치·포인터·버튼의 뗌이 알 수 없는 표면에서 오면 기존 계약대로 조작만 거두고
  drop·클릭을 실행하지 않는다. 살아 있는 다른 표면에서 온 뗌은 활성 조작을 끝내지 않는다.
- 웹뷰에서 시작한 접촉들은 별도로 중계하며 웹뷰의 다중 접촉을 이 제한으로 막지 않는다.

더블 클릭의 연속성은 대상·표면·장치 종류로 구분한다. 접촉마다 달라지는 터치 포인터
id는 보지 않는다. 마우스 클릭과 터치 탭, 펜 접촉은 서로 합쳐 더블 클릭이 되지 않는다.
연속 탭의 거리 한계는 `press_move_tolerance`다. 마우스의 `double_click_distance`(4 물리
픽셀)로는 두 번 탭이 성립하지 않는다.

## 터치 판정과 드래그 우선순위

터치 접촉은 대기·스크롤·일반 드래그·전용 손잡이 조작 단계를 가진다. 누를 때 클릭 대상과
스크롤 후보를 따로 찾는다. 클릭 대상이 없는 스크롤 영역의 여백에서도 후보가 선다. 비활성
가지와 `hit_opaque` 방벽을 넘어 뒤의 후보를 잡지는 않는다. 어느 축에도 후보가 없으면 시간
창 동안 끌기를 보류하지 않는다.

대기 단계는 시작점과의 거리와 최대 이동 거리를 갱신한다. 이동 이벤트를 몇 번에 나눠
받았는지가 판정을 바꾸지 않는다.

1. 시간 창(`pan_start_time`) 안에 `pan_start_distance`를 넘으면 누른 자리부터의 이동으로
   축을 정한다. 그 축으로 흐르는 가장 안쪽 후보가 있으면 스크롤을 시작한다.
2. 시간 창 안에서 시작 거리에 못 미치면 일반 드래그를 보류한다.
3. 축에 맞는 후보가 없거나 시간 창이 지나면 스크롤 후보를 닫는다. 그 뒤 `drag_source`가
   있고 `press_move_tolerance`를 넘으면 일반 드래그를 시작한다.
4. `pointer_drag_target`은 누르는 즉시 전용 조작을 시작하며 스크롤 후보가 아니다. 실제
   이동 액션이 나간 뒤에는 길게 누르기로 메뉴를 열지 않는다. 짧게 눌렀다 떼는 것은
   마우스처럼 클릭이 아니다.

터치용 드래그는 마우스의 6픽셀 임계가 아니라 터치 허용치로 판정한다. 마우스·펜의 드래그
임계와 이벤트 경로는 그대로다.

**초점과 caret은 탭이 확정된 뗌에서 옮긴다.** 스크롤이 될 접촉이 텍스트 칸의 초점과 IME를
빼앗으면 안 되기 때문이다. 빈 곳을 탭하면 초점을 거둔다. 텍스트 칸의 탭은 caret을 놓고
(두 번은 낱말, 세 번부터 전체) 클릭 액션은 아니다. 부모 스크롤 영역이 있는 칸을 빠르게
쓸면 부모가 흐른다. 마우스·펜의 누른 채 범위 선택은 그대로다. 터치 선택 손잡이와 낱말
선택 메뉴는 범위 밖이다. 전용 손잡이는 조작이 이미 시작되므로 누를 때 초점을 옮긴다.

길게 누르기는 대기 단계와 아직 이동 액션을 내지 않은 전용 손잡이에서 가능하다.
접촉 중 한 번이라도 허용치를 넘으면 끝까지
자격을 잃고, 원위치로 돌아와도 복원하지 않는다. 컨트롤러는 시계를 조회하지 않으므로
`long_press_time` 이상 누른 뒤 정상적으로 뗄 때 이벤트 시각으로 판정해 우클릭 액션을
실행한다. 누르고 있는 동안 메뉴를 여는 타이머는 없다.

길게 누르기 대상에 우클릭 액션이 없으면 움직이지 않은 탭으로 처리한다. 우클릭을
실행했다면 클릭·더블 클릭을 함께 실행하지 않고 연속 탭 기록도 거둔다. 허용치를 넘었지만
스크롤이나 드래그가 되지 않은 접촉은 클릭으로 되돌리지 않는다.

탭과 길게 누르기는 누를 때 잡은 대상을 뗄 때의 tree에서 다시 확인한다. 사라졌거나
숨었거나 비활성이 됐거나 새 modal이 누른 자리를 덮었으면 액션 없이 끝난다.
전용 손잡이와 일반 터치 드래그도 이동·drop 전에 원래 대상의 유효성을 다시 확인한다.

## 스크롤 대상과 범용 컨테이너

`scroll_source`에 축(`scroll_axis { vertical, horizontal }`)을 뒤에 붙였다. 기존 초기화는
세로다. 터치 끌기의 후보는 소유자 id·축·배율·스크롤 메시지 factory를 가진 `pan_target`이다.

후보 탐색은 휠과 같은 규칙(그리기 역순, clip, 비활성 가지, `hit_opaque` 방벽)을 따르되
**축이 맞는 것만 임자**다. 축이 다른 흘리는 컨테이너는 방벽이 아니라 지나친다. 그래서 세로
화면 안의 넘친 가로 탭 막대 위를 세로로 쓸면 화면이 흐르고, 옆으로 쓸면 막대가 흐른다.
`hit_opaque`인 컨테이너는 축과 무관하게 방벽이다.

- 표 없는 경로는 `route_pan(tree, x, y, axis)`가 `scroll_source`에서 찾는다.
- `interaction_policy::pan_target_at(tree, x, y, axis)`가 확장 지점이며 기본 구현은
  `route_pan`이다. 표로만 흘리는 컨테이너는 `route_pan(tree, x, y, axis, 표)`와
  `pan_route`(id·축·배율·factory)로 답한다. 표용 탐색도 같은 가시성·활성·clip·방벽
  규칙을 지킨다. 축과 배율을 알 수 없는 휠 표(`scroll_route`)를 세로·배율 1로 추측하지 않는다.

`strip_config::scroll`과 `tab_bar_config::scroll`에 스크롤 factory를 주면 arrange에서
넘칠 때 띠(탭 막대는 안쪽 레인)가 가로 축과 배율로 `scroll_source`를 세운다. 휠·초점
reveal과 같은 factory를 재사용한다. 표 없는 `route_reveal`은 가로 컨테이너에서도 그 축으로
이동량과 보이는 구간을 계산한다. 데모의 탭 막대와 네트워크 가로 띠가 이 경로를 쓴다.

스크롤 중에는 매 이동마다 새 tree에서 누른 자리의 후보를 같은 축으로 다시 묻는다. 같은
소유자 id가 답할 때만 그 최신 factory와 배율로 잇는다. 사라졌거나 비활성이 됐거나 새
modal이 가로막으면 접촉을 취소하며, 취소된 접촉의 뗌은 클릭이 아니다.

각 델타는 이전 물리 위치와 현재 위치의 축 방향 차이를 그 컨테이너의 배율로 나눈다.
손가락을 올리면(가로는 왼쪽으로 밀면) offset이 늘어 휠을 아래로 굴린 것과 같은 쪽이다.
스크롤 시작 때는 누른 자리부터 쌓인 이동을, 정상적인 뗌에서는 마지막 좌표 변화를
반영한다. 경계에 닿았다고 뒤쪽 컨테이너로 넘기지 않는다. 바깥 축으로 넘기는 동작·관성·
회전은 후속 범위다. 같은 [확대 보기](zoom-view-design.md)의 대기·이동 접촉만
둘째 손가락을 받아 핀치로 바뀐다. 하나를 떼면 남은 접촉이 이동을 잇고, 취소는 둘을 함께 거둔다.

## 펜 버튼과 접촉 수명

펜의 비접촉 이동은 누름 없이 hover를 갱신한다. 접촉은 펜촉을 좌클릭, 배럴 버튼을 누른
접촉을 우클릭에 대응시킨다. 접촉 중 배럴 버튼이 바뀌면 어댑터가 이전 버튼의 누름을
취소한 뒤 새 버튼으로 다시 누른다. 좌클릭과 우클릭이 함께 나가지 않고, 진행 중 드래그를
버튼 전환으로 취소해도 drop 액션을 실행하지 않는다.

펜의 캡처 상실·취소는 터치와 같은 명시적 취소 경로를 쓴다. 컨트롤러는 같은 장치가 쥔
조작만 거둔다. 비접촉 이탈(`WM_POINTERLEAVE`)은 hover를 거두지만, 접촉 중의 경계 통과를
접촉 해제로 오인하지 않는다. 터치도 창 밖으로 이동했다고 정상 뗌을 합성하지 않는다.

소비한 펜 이동의 커서는 메시지에 실린 물리 client 좌표로 판정한다. `GetCursorPos`는 이전
마우스 위치를 유지할 수 있으므로 펜 hover의 위치로 쓰지 않는다. 펜이 감지 범위를 벗어나면
마우스 위치로 커서를 다시 판정한다.

## 웹뷰 전달

`webview_host`는 마우스에 `SendMouseInput`을, 터치·펜에 `SendPointerInput`을 쓴다.
UI 스레드에서 복사한 원본(`webview_pointer_input`)을 `ICoreWebView2PointerInfo`로 옮긴다.
픽셀 자리와 접촉 사각형은 웹뷰 왼쪽 위 기준으로 옮기고, himetric 자리와 장치·표시
사각형은 그대로 전달한다.
[WebView2 포인터 입력 문서](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2compositioncontroller?view=webview2-1.0.4191.47)

접촉의 DOWN에서 그 자리의 보이는 웹뷰가 받으면 웹뷰가 임자가 된다. 접촉이 영역 밖으로
나가도, 감춰져 보낼 수 없게 되어도 임자를 유지하며 뒤의 목록 몸짓으로 넘기지 않는다.
감춤·modal 차단 전에 네이티브 접촉에 취소 표식을 실은 뗌을 보낸다. 취소 전송은 가시성
라우팅과 분리해 감춰진 웹뷰도 종료를 받는다. 캡처 상실 때도 같은 방식으로 끝내며,
이미 소비한 `WM_POINTERCAPTURECHANGED`는 0을 반환해 기본 입력 변환을 섞지 않는다. 펜
hover는 매 메시지 자리로 고르고, 웹뷰로 넘어가는 순간 luil hover를 한 번 거두며, 떠난
웹뷰에는 LEAVE를 준다. 마우스 중계는 그대로다.

## 런타임 설정

공개 설정은 [`touch_gesture_config`](../include/luil/ui/ui_interaction.h)이며
`interaction_config::touch`와 `window_config::touch`에 둔다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `pan_enabled` | true | 네이티브 터치 스크롤 활성화 |
| `long_press_enabled` | true | 네이티브 터치 길게 누르기 활성화 |
| `pan_start_distance` | 12 논리 픽셀 | 스크롤 시작 거리 |
| `pan_start_time` | 400ms | 빠른 쓸기와 오래 잡은 드래그를 가르는 시간 창 |
| `press_move_tolerance` | 12 논리 픽셀 | 탭·길게 누르기의 최대 이동, 터치 드래그 시작 거리, 연속 탭 거리 |
| `long_press_time` | 600ms | 길게 누르기 시간 |
| `pinch_enabled` | true | 확대 보기의 두 접촉 핀치 활성화 |
| `minimum_pinch_distance` | 24 논리 픽셀 | 핀치 거리 비율을 잴 최소 간격 |

끄는 것은 bool이다. 거리·시간 0을 "끔"으로 읽는 중의적 계약을 두지 않는다. 거리는
유한한 양수, 시간은 양수이며, `pan_start_time < long_press_time`이어야 한다
(`valid_touch_gesture_config`). 마우스·키보드·펜에 제스처를 켜는 설정은 없다.

- 시작 설정이 잘못되면 창이 시작하지 않고 시작 실패로 알린다.
- 초기값은 `window_config` → `app_host::config` → `interaction_controller`로 전달한다.
- 실행 중 변경은 `app_host::set_touch_gesture_config`가 검증 뒤 최신 값 slot에 게시하고,
  잘못된 값은 거짓을 돌려주며 직전 설정을 유지한다. 입력 스레드는 다음 이벤트 처리 전이나
  받기 대기의 시간 만료에서 적용한다. 게시 성공은 적용 완료가 아니며, 이미 접수된 입력
  큐와의 순서를 묶어 주지 않는다.
- 진행 중 접촉의 거리·시간은 누를 때의 값이다. 스크롤을 끄면 대기·스크롤 중인 접촉을,
  길게 누르기를 끄면 대기 중인 접촉을 취소하고 남은 이벤트를 삼킨다. 핀치를 끄면
  진행 중인 두 접촉을 함께 취소한다. 다시 켜도 내려가 있는
  손가락이 새 접촉이 되지 않는다. 설정은 마우스·펜 조작과 웹뷰 자체의 터치 동작을 바꾸지
  않는다.
  손잡이에서 길게 누르기를 끄면 조작은 이어가고 메뉴 후보만 거둔다. 다시 켜도 기존
  접촉의 메뉴 후보를 되살리지 않는다.

## 기존 policy와 액션 계약

`interaction_policy::on_press(tree, element, event)`는 활성 element를 왼쪽 버튼·터치
접촉·펜촉으로 누른 순간의 관찰 hook이다. 돌려준 액션은 그 누름의 다른 액션(손잡이의 누름)
보다 앞선다. 장치는 `event.device`로 알 수 있지만 그 자체로 제스처 판정을 대신하지 않는다.
터치에서는 이 누름이 탭·스크롤·길게 누르기 중 무엇이 될지 아직 모른다. 클릭 대상이 없는
여백에서는 부르지 않는다. 앱이 누름에서 화면을 바꾸면 이후 제스처는 다음 tree에서 임자를
다시 확인한다.

터치 탭·터치 길게 누르기·펜 클릭도 마우스와 같은 액션 실행 경로를 쓴다. 대상의 활성 검사와
`on_click` 알림을 경로마다 지킨다. 스크롤로 끝난 접촉은 `on_click`을 부르지 않는다.

## 검증

### UIA와 네이티브 입력 자동화의 역할

터치·펜 경로를 검증하는 자동화는 필요하다. UIA 패턴 실행만으로 입력 장치의 종류나
`WM_POINTER*` 시퀀스를 재현할 수는 없으므로 UIA에 터치·펜 전용 패턴을 추가하지 않는다.
UIA는 대상 찾기와 조작 결과 확인에 쓰고 입력의 출처는 Win32 주입 계층이 보존한다.
[UIA control pattern 문서](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-control-patterns-overview)

| 계층 | 역할 | 검증 범위 |
| --- | --- | --- |
| 순수 회귀 테스트 | raw 이벤트·시각·tree를 직접 구성 | 소유권, 혼합 입력, 옵션 변경, tree 교체, 클릭·메뉴·drop 억제 |
| UIA | AutomationId로 대상과 물리 경계를 찾고 결과를 다시 읽음 | 값·선택·초점·메뉴·스크롤 결과와 접근성 계약 |
| 네이티브 통합 테스트 | 합성 포인터 장치를 만들어 실제 메시지 경로로 주입 | 장치 분류, `GetPointer*Info`, 캡처, 호환 마우스 중복, 웹뷰 중계 |
| 실제 장치 확인 | 터치 화면·펜·원격 환경에서 조작 | 드라이버, 팜 리젝션, 필압·기울기, DPI·다중 모니터 차이 |

Win32 통합 테스트에는 [`CreateSyntheticPointerDevice`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createsyntheticpointerdevice)와
[`InjectSyntheticPointerInput`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-injectsyntheticpointerinput)을
사용한다. 둘은 PT_TOUCH와 PT_PEN을 지원하며 Windows 10 1809 이상이 필요하다.
`SendInput`으로 마우스를 움직이거나 `PostMessage(WM_POINTER*)`만 보내는 방법은 장치 정보
조회와 OS 캡처를 검증하지 못하므로 대체 수단으로 쓰지 않는다.

주입은 사용자의 입력 데스크톱에 영향을 줄 수 있다. 전용 대화형 테스트 VM에서 별도
통합 테스트로 실행하고 일반 단위 테스트에 자동으로 포함하지 않는다. 포인터 장치 생성이나
주입이 실패하면 환경 제약으로 명시하며 성공으로 처리하지 않는다. 생성한 장치·창·프로세스는
테스트 종료 때 정리한다. UIA로만 조작하는 격리 데스크톱과 입력 주입이 가능한 데스크톱은
구분해야 한다.

통합 테스트의 우선 시나리오는 터치 탭·팬·길게 누르기, 펜촉·배럴·Shift 선택·호버,
마우스와 펜의 교차 입력, 캡처 상실·late UP, 진행 중 옵션 변경, 웹뷰 감춤·modal 차단이다.
웹뷰는 페이지가 기록한 `pointerType`과 DOWN 뒤 UP/CANCEL의 짝도 확인한다. UIA Invoke나
RangeValue로 동일한 화면 결과를 만들었다는 사실만으로 네이티브 입력 검증을 통과시키지 않는다.

`luil_pointer_integration`은 UIA 클라이언트와 별도 프로세스의 luil 테스트 창을 함께 제공한다.
외부 UIA 스크립트 없이 Win32 합성 터치·펜 장치를 사용한다. 테스트 창은 수신한 네이티브
메시지 수와 앱 결과를 UIA 라벨로 공개하며, 텍스트 선택은 Text 패턴으로도 읽는다.
WebView 페이지는 `pointerType`, DOWN·UP·CANCEL과 짝 없는 종료를 호스트에 보낸다.
스크롤 초기화와 옵션 변경만 UIA 패턴으로 수행한다.

전용 대화형 Windows 테스트 환경에서 다음처럼 빌드·실행한다.

```powershell
cmake --preset vs2026-tests -DLUIL_BUILD_POINTER_INTEGRATION_TESTS=ON -DLUIL_ENABLE_WEBVIEW=ON
cmake --build --preset vs2026-tests-debug --target luil_pointer_integration
./build/vs2026-tests/tests/Debug/luil_pointer_integration.exe --interactive
```

빌드 옵션은 기본 OFF이고 `LUIL_BUILD_TESTS=ON`이 필요하다. 일반 `ctest`에는 등록하지
않는다. 실행 인자 없이 시작하면 입력을 주입하지 않고 건너뜀 코드 77로 끝난다.
`--interactive` 실행 중에는 실제 입력 데스크톱, 대상의 가려짐과 포그라운드를 확인한다.
장치 생성·주입·UIA 조회·assertion 실패는 코드 1이며 오류와 마지막 관측 상태를 남긴다.
WebView를 켠 빌드에서는 SDK뿐 아니라 런타임·Direct3D와 로컬 페이지 로딩도 성공해야 한다.
WebView를 끈 빌드는 해당 시나리오를 SKIP으로 표시한다.

자동화 범위는 터치 탭·길게 누르기·팬, 진행 중 팬·길게 누르기 비활성화와 대상
비활성화, 두 손가락의 뗌 순서와 잔여 손가락의 조작 억제, 모달이 탭·팬을 덮는 경우,
펜촉·접촉 중 배럴 전환·호버와 텍스트 커서·긴 누름·끌기·지우개·Shift 선택,
마우스 긴 누름·끌기, WebView 터치·펜 시퀀스와 접촉 중 숨김·모달 뒤 late UP 억제다.
실패에서도 접촉·Shift·마우스
버튼을 해제하고 테스트 창·프로세스·임시 웹 프로필을 정리한다.

교차 입력, 취소 표식, 창 최소화에 의한 OS 캡처 상실, WebView 다중 접촉은 네이티브 탐색도
실행한다. 두 손가락은 한 장치의 같은 프레임에 실으며, 네이티브 프레임·메시지 기록으로
입력이 의도한 대로 도착했는지 먼저 확인한다. 탐색 조건이 성립하지 않으면 SKIP으로 남기고
통과 수에 넣지 않는다. 실제 접촉이 두 개 도착했는데 WebView의 DOWN·UP/CANCEL 짝이
맞지 않으면 실패다. 캡처 상실은 실제 `WM_POINTERCAPTURECHANGED` 수신을 요구한다.

2026-10-02의 RDP 세션에서는 교차 장치 입력 전 합성 터치가 정상 UP으로 끝났고, 최소화는
포인터 캡처 상실 메시지를 발생시키지 않았다. 주입한 취소 표식과 WebView의 두 접촉도
검증에 필요한 형태로 수신되지 않아 해당 다섯 탐색은 미검증으로 남았다. RDP가 원인이라고
확정하지 않는다. 접촉 중 취소·소유권 전환의 순수 회귀 테스트는 별도로 통과했다.
같은 세션의 150% 배율(144 DPI), WebView2 활성화 빌드에서 네이티브 시나리오 25개와
전체 회귀 776개(53,534 assertion)가 통과했다. Surface 터치스크린과 Slim Pen 2의 장치
인식도 확인했지만 실제 센서 입력을 수행한 결과로 세지는 않는다.
합성 입력의 통과는 실제 장치의 드라이버·필압·팜 리젝션 검증을 대신하지 않는다.

순수 변환과 컨트롤러 동작은 [touch_input_tests.cpp](../tests/touch_input_tests.cpp)와
[surface_input_tests.cpp](../tests/surface_input_tests.cpp)가 확인한다.

| 검증 대상 | 통과 조건 |
| --- | --- |
| 장치 구분 | 같은 좌표·시각의 마우스·펜은 제스처가 없고 터치만 스크롤 |
| 마우스·키보드 | 기존 클릭·더블 클릭·드래그·휠·키 라우팅 테스트 유지 |
| 펜 | 배럴 전환은 취소 뒤 우클릭만, 호버·이탈, 지우개 삼킴 |
| 연속 탭 | 다른 터치 id의 연속 탭은 더블 클릭, 다른 장치의 클릭과 섞이지 않음 |
| 이동 이벤트 빈도 | 8→20픽셀과 20픽셀 한 번이 같은 스크롤 |
| 빈 곳·텍스트 | 여백에서 스크롤, 칸을 쓸면 부모가 흐르고 초점 불변, 탭은 뗄 때 caret |
| 이동 이력 | 멀리 갔다 돌아온 접촉과 실제 손잡이 조작은 길게 누르기 불가 |
| 라우팅 | 축이 맞는 가장 안쪽 후보, clip·비활성 가지·방벽, 표용 탐색 |
| tree 변경 | 흘리던 창 삭제·탭 대상 위 modal·표면 삭제에서 액션 없이 취소 |
| 접촉 수명 | 다른 id의 뗌·추가 손가락·마우스 누름·입력 큐 유실에서 잘못된 클릭·drop 없음 |
| 시각 | 성능 카운터·tick 변환, tick 순환, 미래 값 |
| 런타임 설정 | 잘못된 값 거절, 진행 중 비활성화와 재활성화 |

현재 테스트 실행 파일의 통과만으로 네이티브 입력 지원 완료를 판정하지 않는다. 다음은
실제 터치 화면과 펜에서 확인해야 한다.

- 수신 메시지 종류와 순서(ENTER·LEAVE 포함), 표면별 `dpi`가 배율로 맞게 실리는지
- 소비한 시퀀스 뒤에 마우스 호환 메시지가 남는지와 출처 표식에 의한 중복 거름
- 소비한 펜 hover에서 `WM_SETCURSOR` 없이 커서가 맞게 바뀌는지
- 캡처 상실 뒤 UP이 오는지, 오지 않을 때 다음 접촉이 정상인지
- `SendPointerInput`의 좌표 규약(픽셀·접촉 사각형 이동, himetric 원본 전달)과 취소 표식
- 100%·150%·200% DPI와 음수 화면 좌표(왼쪽·위쪽 모니터)
- 터치 종류가 보존되는 원격 연결과 마우스로 변환되는 원격 연결
