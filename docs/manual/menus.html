메뉴와 메뉴 막대

luil의 메뉴는 앱이 열림을 쥔 popup 하나에 실은 menu_element다. 메뉴는 항목을 그리고 고른 키를 메시지로 낼 뿐이다. 떠 있는지, 하위 메뉴가 어디까지 열렸는지, 메뉴 막대가 어느 항목에 섰는지는 모두 앱 상태다. 키보드 탐색은 input thread의 controller가, 닫힘 계기는 UI thread의 표면이 맡는다.

  • 우클릭·길게 누르기·Shift+F10으로 여는 명령 목록이다.
  • popup 표면에 그린다. Windows·macOS에서는 창 밖으로 나갈 수 있다.
  • 하위 메뉴, 체크·라디오, 구분선, 오른쪽 단축키 열.

  • 드롭다운 만들기에서 다룬다.

  • 콤보 만들기에서 다룬다.

개념: popup은 frame의 별도 표면이다

메뉴는 주 tree의 자식이 아니다. 앱이 frame마다 원하는 popup 목록을 선언하면, UI thread가 그 목록에 맞춰 표면을 만들고 옮기고 지운다.

우클릭 한 번이 지나가는 길

사용자카드를 우클릭한다. 터치는 600ms 길게 누르기, 키보드는 Shift+F10이다.
input threadcontroller가 카드의 right_click 액션을 실행한다. 액션은 누른 자리(물리 픽셀)를 담은 앱 메시지를 만든다.
logic thread앱의 handle이 "열림"과 자리를 상태에 적는다.
logic threadmake_frame()이 menu_config를 짓고 popup으로 싸서 frame->popups에 싣는다.
UI threadhost가 popup 표면을 만들어 그린다. 표면은 활성화되지 않는다. 키보드 초점은 연 창에 그대로 있다.
input thread↑/↓는 controller의 강조만 옮긴다. Enter·클릭은 select(key)를, 있으면 이어서 after_select를 낸다.
logic thread앱이 명령을 실행하고 열림을 지운다. 다음 frame에 popup이 빠지면 표면이 사라진다.

factory는 logic thread 밖에서 불린다. select·open_submenu·set_state는 input thread(포인터·키)나 UI thread(보조 기술)에서, dismiss는 UI thread에서 불린다. 그래서 값만 캡처한 람다여야 하고, 앱 상태는 logic thread의 handle에서만 바꾼다.

  1. popup은 자기 (0,0)에서 시작하는 분리 tree를 가진다. make_menu_popup이 메뉴 하나짜리 tree를 짓는다.
  2. anchor가 비면 주 창이다. 보조 창 id나 같은 frame의 다른 popup id도 된다. 위 그림의 하위 메뉴는 부모 popup id에 앵커했다.
  3. x·y·width·height는 앵커 표면 client의 논리 픽셀이다. 하위 메뉴의 x는 부모 메뉴의 폭이다.
  4. Windows·macOS에서는 popup마다 활성화되지 않는 창이 서고, Android·iOS에서는 주 표면 위에 겹쳐 그린다.
  • 선언이다. 앱이 원하는 popup 전체를 ui_frame::popups에 싣는다. 목록에 있으면 서고, 빠지면 지워진다. UI thread는 열림 상태를 따로 들지 않는다.
  • id는 frame 안에서 유일하고 비어 있지 않아야 한다. 보조 창 id와 같은 이름 공간이다. 빈 id, 겹친 id, 크기가 0 이하인 popup은 오류 없이 서지 않는다 — 겹친 id는 둘 다 서지 않는다 (코드에서 확인한 동작).
  • 대조. 같은 id·같은 앵커면 자리·크기·tree·dismiss를 갱신한다. 앵커가 바뀌면 지웠다가 다시 만든다. 부모 popup을 먼저 만드는 순서는 라이브러리가 정하고, 없는 앵커나 순환은 만들지 않는다.
  • 활성화하지 않는다. Windows의 popup 창은 WS_EX_NOACTIVATE이고 누름에도 MA_NOACTIVATE로 답한다. 키는 앵커 창에서 온다. 메뉴 항목은 Tab 자리가 아니어서, 메뉴가 열려도 키보드 초점은 연 자리에 남고 강조는 초점과 따로 선다.

앵커와 자리

  • 우클릭 액션의 ui_action_context::x·y는 그 표면 tree의 물리 픽셀이다. popup의 x·y에는 배율로 나눠 넣는다. 나누지 않으면 고배율에서 메뉴가 엉뚱한 곳에 선다.
  • menu_popup_config::below(field_popup_anchor)를 주면 make_menu_popup이 폭·높이를 잰 뒤 place_field_popup으로 자리를 정한다. 아래가 모자라면 위로 뒤집는다. 그때 x·y는 쓰지 않는다. 규칙은 필드 popup 자리 실습에서 해 볼 수 있다.
  • 화면 좌표로 바꾸고 모니터 작업 영역 안으로 미는 일은 UI thread가 한다. Windows는 하위 메뉴가 작업 영역 오른쪽을 넘으면 부모의 왼쪽으로 뒤집은 뒤 안으로 민다. macOS도 같은 규칙이다.
  • 작업 영역보다 긴 popup은 작업 영역 높이로 줄고 내용을 흘린다. Windows에는 위·아래 화살표 칸(16 논리 픽셀)이 서고 키보드 강조가 칸에 가리지 않게 따라간다. macOS에는 화살표 칸이 없고 휠로만 흘린다.
  • 다듬은 최종 자리가 필요하면 ui_popup::placed를 준다. 앵커 기준 논리 픽셀로, 처음 서거나 바뀔 때만 온다. make_menu_popup은 이 칸을 채우지 않는다.

ui_popup::dismiss는 계기(popup_dismiss_reason)를 받아 메시지 하나를 돌려주는 factory다. UI thread는 계기를 감지해 그 메시지만 낸다. popup을 빼는 것은 앱이다.

Esc가 지나는 차례

UI threadIME가 조합 중이면 입력기가 먼저 먹는다. 메뉴 막대가 선 동안은 입력기에 주지 않는다.
UI thread표면이 Esc를 controller보다 먼저 popup에 묻는다. 사슬(앵커가 popup인 popup)이 있으면 가장 깊은 popup 하나에만 묻고, 사슬이 없으면 모든 popup에 묻는다.
UI thread누구든 메시지를 냈으면 Esc는 거기서 삼켜진다. 가장 깊은 popup이 빈 액션을 내면 다른 popup에는 묻지 않고 Esc를 controller로 보낸다.
input threadcontroller의 메뉴 경로가 받는다. 깊이 > 0이면 그 메뉴의 close_submenu, 깊이 0이면 정책의 close_menu()다 (막대의 메뉴면 막대 상태).

Esc의 뜻은 앱의 dismiss가 먼저 정한다하위 메뉴 popup의 dismiss가 Esc에 "메뉴 전체 닫기"를 내면 Esc 한 번에 사슬이 다 닫힌다. "하위 메뉴만 닫기"를 내거나 빈 액션을 돌려주면 한 단계만 닫힌다 — 앞의 것은 앱 메시지로, 뒤의 것은 controller의 close_submenu로. 데모 작업대는 앞의 방식(전부)이고, 데모 셸의 메뉴 막대는 한 단계 방식이다.

비modal이지만 열린 동안 키를 독점한다

  • 메뉴는 초점 가둠이 아니다. 뒤 화면을 누르면 그 누름은 그대로 진행하고, popup은 pointer_press_outside로 닫자고 할 뿐이다.
  • 그러나 controller는 메뉴 kind의 container가 어느 표면 tree에든 서 있으면 "메뉴가 열렸다"로 본다. 메뉴가 쓰지 않은 키는 삼킨다. 예외는 그 메뉴 표면 안에서 초점을 가진 글 칸(검색 칸)이 쓰는 편집 키다. 앱 정책의 on_key로는 흐르지 않는다.
  • 여러 메뉴가 서 있으면 menu_config::depth가 가장 큰 것이 키를 받는다.
  • 메뉴 요소는 hit를 흡수한다. 항목 사이 여백이나 구분선을 눌러도 아래 요소로 새지 않는다.

메시지와 상태

여는 계기: 우클릭 액션

터치의 길게 누르기와 펜의 배럴 버튼도 right_click이다. 키보드의 Shift+F10은 초점 요소에서 위로 올라가며 이 액션을 찾아 요소 한가운데 좌표로 실행한다. 액션 하나로 세 입력이 함께 선다.

열린 동안 popup을 짓는다

  • 자리는 물리 픽셀(card_menu_x)을 배율로 나눈 논리 픽셀이다. 높이는 menu_element::height_for가 준다. tree는 물리 크기로 배치한다.
  • 항목 { key, label, icon }은 집합 초기화다. menu_item_config의 칸 차례가 key, label, icon, enabled, separator_above…이기 때문이다.
  • 비활성 항목(remove.enabled = false)은 흐리게 그리고, 눌리지 않고, 키보드 탐색이 건너뛴다.
  • close_on_any는 어느 계기에서든 닫자는 factory다 (같은 파일 75–76행).

handle의 갈래와 정책

고른 뒤 닫는 것도 앱이다. menu()가 메뉴 kind 짝을 돌려줘야 ↑/↓/Enter가 메뉴의 것이 된다. 기본 구현은 std::nullopt라서, 재정의하지 않으면 메뉴가 떠도 키가 뒤 화면으로 간다. close_menu()는 Esc가 controller의 메뉴 경로까지 왔을 때만 쓰인다. popup의 dismiss가 Esc에 메시지를 내면 여기까지 오지 않는다.


고른 뒤 caret이 사라진다메뉴 항목을 마우스로 누르면 키보드 초점이 지워진다. 메뉴 항목은 Tab 자리가 아니고 누름에 초점을 지키지도 않아서, 누를 때 controller가 초점을 비운다. 글 칸에서 연 메뉴라면 고른 뒤 caret이 없다. Enter·접근 키로 고르면 초점은 그대로다. 코드에서 확인한 동작이고 test가 잠그지 않았다. 되돌려야 하면 앱이 ui_frame::focus에 focus_request를 싣는다.

만들기: make_menu_popup, 체크 항목, 단추로 열기

데모의 "메뉴와 팝업" 페이지는 같은 일을 make_menu_popup으로 한다. 폭·높이·배율·분리 tree를 한 번에 조립하고, 폭은 비우면 글로 잰다.

여는 계기 둘: 우클릭과 단추

카드의 우클릭과 "문서 작업…" 단추가 같은 메시지를 낸다. 단추를 Enter·Space로 누르면 액션의 좌표는 단추의 한가운데다. 그래서 키보드로 열어도 메뉴가 단추 위에 선다.

열기·닫기·고르기

이 페이지는 "한 번에 popup 하나만"을 열린 임자 하나(open_popup_)로 지킨다. show_popup은 그 값을 갈아 끼울 뿐이라 앞의 popup은 다음 frame에 저절로 빠진다. popup 목록이 앱 상태라서 라이브러리는 이것을 강제하지 못한다.

메뉴 popup

  • 체크 항목은 kind = menu_item_kind::check와 checked다. 라디오는 radio다. 실행 메시지는 셋 다 같은 select이고, 다음 frame의 checked를 앱이 정한다.
  • 체크 항목은 checked일 때 체크 글리프를, 라디오는 점을 그린다. 이 둘은 icon을 그리지 않는다.
  • 구분선은 항목이 아니라 그 아래 항목의 separator_above다. 9 논리 픽셀 띠의 한가운데에 선을 긋는다.
  • corner·border는 이 페이지의 모양 설정을 popup에 넘긴다 (모양).

만들기: 하위 메뉴와 라디오 항목

하위 메뉴는 라이브러리가 띄우지 않는다. 부모 메뉴가 open_submenu(key)를 내면 앱이 열림 경로를 적고, 자식 메뉴를 실은 두 번째 popup을 부모 popup에 앵커해 짓는다.

데모의 변경 작업대는 행 메뉴에 "정렬" 하위 메뉴를 둔다. 라디오 항목이 지금 정렬 열을, 체크 항목이 방향을 보인다.

  1. 라디오 셋과 체크 하나다. checked는 앱 상태에서 바로 계산한다. 체크 항목은 separator_above로 라디오 묶음과 가른다.
  2. "정렬" 항목에 children을 준다. 그러면 오른쪽에 ›를 그리고 클릭·Enter·→·hover가 select 대신 open_submenu(key)를 낸다. opened_key는 앱이 든 열림 경로다 — 그 항목은 강조로 그려지고 보조 기술에 펼침으로 읽힌다.
  3. 붙을 항목 줄의 위 끝을 센다. menu_padding에서 시작해 구분선마다 menu_separator_height, 앞 항목마다 menu_row_height()를 더한다. 상수 menu_item_height가 아니라 함수를 써야 큰 글자에서 어긋나지 않는다.
  4. 컨텍스트 메뉴답게 자리는 우클릭 좌표 ÷ 배율이다. dismiss 하나를 부모와 자식이 함께 쓴다. 어느 계기든 메뉴 전체를 닫는다.
  5. 자식 메뉴에는 depth = 1, parent_surface(부모 popup id), anchor_key(연 항목 키), close_submenu를 준다. popup의 anchor는 부모 popup id이고, x는 부모 폭, y는 줄의 위 끝에서 menu_padding을 뺀 값이다. 그래야 자식의 첫 줄이 부모의 그 줄과 나란하다.
  • controller는 depth(부모 + 1)·parent_surface(부모 popup id)·anchor_key(부모의 opened_key) 셋이 다 맞는 메뉴를 "부모가 연 자식"으로 본다. 하나라도 어긋나면 잎 형제 위에 멎었을 때의 hover 닫힘이 그 자식을 찾지 못해, 자식이 계속 선다.
  • 자식이 있는 항목은 고른 것이 아니라서 after_select를 내지 않는다. 이미 연 항목을 다시 눌러도 open_submenu다 (닫지 않는다).
  • 라디오 항목이 하나라도 있는 메뉴는 보조 기술에 선택 container로 읽힌다.
  • 이 데모의 자식 popup은 Esc에도 메뉴 전체를 닫는다. 주석은 "왼쪽·Esc가 한 단계만 닫는다"고 적지만, 표면이 Esc를 가장 깊은 popup의 dismiss에 먼저 묻고 그 답이 "전부 닫기"라서다 (Esc가 지나는 차례). ←는 controller의 close_submenu로 가서 한 단계만 닫는다.

만들기: 여러 단계의 하위 메뉴

저장소의 예는 모두 깊이 1까지다. 깊이 2 이상도 규칙이 같다. 열림 경로를 키의 목록으로 들고, 깊이 d의 메뉴가 open_submenu로 path[d]를 바꾸고 close_submenu로 자기를 닫는다.

  • 열림 경로 메시지 menu_path_intent { depth, key }는 "깊이 d부터 아래를 버리고, 키가 있으면 그 자리에 둔다"는 절대 명령이다. 같은 메시지가 거듭 와도 결과가 같다. 빈 키가 곧 "깊이 d의 자식을 닫아라"다.
  • 자식 메뉴의 parent_surface는 부모 popup id이고, anchor_key는 부모의 opened_key와 같아야 한다. 그래야 hover 닫힘이 그 자식을 찾는다.
  • 깊이 d popup의 dismiss가 Esc에 "깊이 d만 닫기"를 내므로 Esc가 한 단계씩 닫는다. 표면이 가장 깊은 popup에만 Esc를 묻기 때문이다. 사슬이 짧아지면 controller가 강조를 부모의 그 항목에 되돌린다.
  • 키보드(→·Enter·접근 키)로 연 자식은 첫 활성 항목이 강조된 채 서고, hover로 연 자식은 강조 없이 선다. 강조가 없는 자식에서 첫 ↓는 첫 활성 항목으로 간다.
  • 앱의 make_frame은 frame->popups = make_menus(state_, view_items(), scale)처럼 싣고, 정책에는 menu_policy를 쓴다. 고르면 after_select가 따로 닫기 메시지를 보낸다.

만들기: 메뉴 막대 (파일·편집·보기, 접근 키)

막대는 주 tree에 서는 menu_bar_element이고, 열린 메뉴는 make_menu_bar_popup이 그 항목 아래에 짓는 popup이다. 막대의 상태 menu_bar_state는 앱이 들고 set_state 메시지로만 바뀐다.

데모 셸의 shell_menu가 막대 하나와 그 메뉴를 모두 짓는 완결된 예다. 상태·메시지·막대·popup이 한 클래스에 있다.

메시지와 상태

항목: 접근 키와 단축키 글

  • 단축키 글은 shortcut_label이 플랫폼에 맞게 쓴다. Windows는 "Ctrl+S", macOS는 "⌘S"다. shortcut_text는 그리기만 한다 — 실행은 명령표의 몫이다.
  • access_key는 영문자나 숫자 하나다. 라벨에 그 글자가 없으면 "새로 만들기(N)"처럼 덧붙여 그린다. 접근 키는 막대에서 연 메뉴에서만 먹는다.

handle과 막대 설정

막대가 쉬거나 다른 메뉴로 옮기면 열린 하위 메뉴도 앱이 닫는다. 한글 라벨에는 접근 키 글자가 없어 "파일(F)"로 그린다. 접근 이름은 "파일" 그대로이고 키는 "Alt+F"로 따로 읽힌다.

열린 메뉴와 하위 메뉴 popup

  1. 막대가 열렸고(open) 선 항목이 있을 때만 짓는다. 메뉴 항목은 current로 고른다.
  2. 고름, 하위 메뉴 열기·닫기, 열림 경로. 컨텍스트 메뉴와 똑같다. owner는 비워 둔다 — make_menu_bar_popup이 막대의 current로 채운다.
  3. id와 배율만 준다. make_menu_bar_popup이 그 항목 아래 자리(below, 간격 0), Esc와 그 밖의 닫힘, 고른 뒤 막대를 쉬게 하는 after_select를 채운다. limit은 주 창 client(물리 픽셀)다.
  4. 붙을 항목 줄의 위 끝을 센다. 앞 항목의 구분선도 더한다.
  5. 고르면 하위 메뉴와 막대가 함께 닫히도록 after_select에 쉬는 상태를 준다. depth·parent_surface·anchor_key로 부모와 짝을 짓는다.
  6. 자식 popup의 dismiss는 Esc에 "하위 메뉴만 닫기"를, 그 밖의 계기에 "막대 쉬기"를 낸다. 표면이 Esc를 가장 깊은 popup에 먼저 묻기 때문에 이 답이 곧 Esc의 뜻이다.
  7. 부모를 먼저, 자식을 뒤에 싣는다. 목록의 뒤가 위다.

셸에 잇기

  • 막대를 이번 frame에 배치해 두고 그 포인터로 같은 frame의 popup 자리를 잰다. 포인터는 그 frame이 게시되기 전까지만 쓴다.
  • 막대 항목은 Tab 자리가 아니고, 눌러도 글 칸의 초점을 가져가지 않는다.
  • 막대가 키를 받으려면 보이고, 켜져 있고, set_state가 있고, 초점 가둠(대화 상자) 밖이 아니어야 한다. 대화 상자가 떠 있으면 Alt에 반응하지 않는다.
  • 메뉴를 고르면 make_menu_bar_popup이 채운 after_select가 set_state({})를 내 막대가 쉰다. 키보드 탐색은 컨텍스트 메뉴와 같은 정책의 menu()로 켠다.

make_menu_bar_popup은 앱의 dismiss를 덮어쓴다막대에 set_state가 있으면 popup의 dismiss를 "Esc면 { current, false, keyboard }, 그 밖이면 {}"로 바꾸고, 비어 있는 after_select를 set_state({})로 채운다. 넘긴 popup.dismiss는 쓰이지 않는다. 막대 메뉴의 닫힘을 바꾸려면 돌려받은 ui_popup의 dismiss를 다시 단다.

만들기: 명령표에서 항목과 단축키 열을 짓기

menu_item_config::shortcut_text는 표시만 하는 열이다. 단축키를 실행하는 일치 판정은 명령표(app_command·match_command)가 한다.

menu_item_from은 명령 하나를 항목으로 옮긴다. 라벨·활성·체크와, 실제로 쓰는 첫 단축키의 글을 채운다. 같은 명령표를 앱 정책의 마지막 키 단계에서 맞춘다.


메뉴가 열린 동안에는 단축키가 오지 않는다메뉴가 쓰지 않은 키는 controller가 삼킨다. 그래서 메뉴가 떠 있을 때 Ctrl+W 같은 단축키는 on_key까지 가지 않는다. 메뉴 막대가 "선" 동안(열리지 않았어도)도 막대의 것이 아닌 키를 삼킨다. 단축키 글을 메뉴에 그렸다고 그 키가 메뉴 안에서 먹는 것은 아니다.

만들기: 필드 아래에 붙는 메뉴

분할 버튼과 드롭다운 단추의 메뉴다. below가 메뉴 크기를 잰 뒤 자리를 정하고, 아래가 창 밖으로 넘치면 위로 뒤집는다.

  • field는 이번 frame에 배치한 필드의 bounds()(물리 픽셀), limit은 앵커 표면의 client 사각형이다. 간격은 기본 2 논리 픽셀이다.
  • after_select가 고른 뒤의 닫기 메시지를 따로 낸다. 잎 항목에서만 낸다.
  • 닫기 메시지는 절대 상태(field_menu_intent { owner, false })라 바깥 누름 닫기와 겹쳐 두 번 와도 결과가 같다.
  • 자리 규칙(아래 기본, 위로 뒤집기, 가로 맞춤과 밀기)은 필드 popup 자리 실습에서 원본을 옮긴 함수로 해 볼 수 있다.

만들기: 보조 창에 앵커한 메뉴

anchor가 보조 창 id면 자리는 그 창 client 기준 논리 픽셀이고, 배율도 그 창의 것이다.

  • 도구 창은 주 창과 다른 모니터에 있을 수 있다. 그래서 배율을 도구 창의 metrics에서 꺼낸다.
  • popup 안에 검색 칸이 있다. popup은 키보드 초점을 받지 못하지만, 검색 칸의 IME 조합은 앵커 창(도구 창)의 입력 session이 대신 본다.
  • 검색 칸이 있는 popup은 창 이동·활성 전환에는 남는다(search_popup_stays). 남기는 계기에 빈 액션 luil::input_action {}을 돌려준다.
  • make_menu_popup을 쓰지 않고 손으로 지은 popup이라 메뉴의 사각 선을 직접 끈다. popup_corner_radius는 그 모서리의 실제 반지름(논리 픽셀)이다.

만들기: popup 모양 — 모서리·경계·배경 효과

corner·border·backdrop은 menu_popup_config에서 ui_popup으로 그대로 옮겨진다. 둥근 창이면 메뉴 자신의 사각 선은 꺼진다.

  • 배경 효과는 popup에서 window_backdrop::acrylic만 선다. 효과가 선 표면에서는 메뉴가 몸통을 칠하지 않아 효과가 비친다.
  • corner를 비우면 내장 스타일의 popup.corner(기본 popup_corner::system)다. 실행 중에 스타일을 바꾼 앱(ui_frame::style)은 그 값을 넘긴다. 둥근 모서리를 쓸 수 없는 환경이면 무엇을 주든 직각이다.
  • 폭을 재는 font_size·weight도 비우면 내장 스타일 값이다. 큰 본문 글자로 바꾼 앱이 넘기지 않으면 글이 잘린다.
  • Windows 11의 system은 작게 둥근 창(반지름 4)이고, 원격 세션처럼 둥근 모서리를 못 쓰면 직각으로 물러선다.

만들기: 키보드와 터치로 컨텍스트 메뉴 열기

우클릭 액션 하나만 달면 된다. Shift+F10과 길게 누르기가 같은 액션을 실행한다.

  • Shift+F10: controller가 초점 요소에서 root 쪽으로 올라가며 right_click 액션을 가진 첫 활성 조상을 찾아, 그 한가운데 좌표로 실행한다. 초점 가둠 밖으로는 올라가지 않는다. 그래서 초점이 카드 안의 단추에 있어도 카드의 메뉴가 열린다.
  • 키보드의 메뉴 키(Application 키)를 키 이벤트로 옮기는 코드는 저장소에서 찾지 못했다. 확인되는 것은 Shift+F10뿐이다.
  • 터치: 움직이지 않고 long_press_time(기본 600ms) 동안 누르면 손을 떼기 전에 우클릭 액션이 나간다. 우클릭 액션이 없는 대상은 길게 눌러도 탭이다.
  • 키보드로 연 컨텍스트 메뉴는 강조 없이 선다. 첫 ↓가 첫 활성 항목을, 첫 ↑가 끝 활성 항목을 고른다.

키보드와 접근성

메뉴 키는 메뉴 요소가 아니라 input thread의 controller가 처리한다. 막대 키는 menu_bar_element::handle_key가, 열린 메뉴의 키는 controller의 메뉴 경로가 받는다.

키가 지나는 차례

  1. 플랫폼 표면: IME 조합 중이면 입력기가 먼저 먹는다(막대가 선 동안은 주지 않는다). Esc는 popup의 dismiss(escape_key)에 먼저 묻는다 — 누가 메시지를 내면 키는 거기서 끝난다.
  2. controller: 키 잡기 칸 → 메뉴 막대의 활성화 키(Alt 단독·F10·Alt+접근 키)와 열리지 않고 선 막대의 모든 키 → 열린 메뉴 → 그 메뉴 표면의 글 칸 → 나머지는 삼킨다.
  3. 그 뒤에야 Shift+F10 컨텍스트 메뉴, 실행 키·Tab·글 칸·값·묶음·키 처리기·가둠의 Esc·기본 단추, 끝으로 앱 정책의 on_key다.

  • 메뉴 안의 접근 키는 막대가 선 동안만, 수식 키 없이 받는다. 맞는 활성 항목이 하나면 실행한다(하위 메뉴면 키보드로 연 것처럼 연다). 여럿이면 지금 강조 다음 것으로 강조만 옮기고 끝에서 처음으로 돈다. 맞는 것이 없으면 삼킨다.
  • 컨텍스트 메뉴·명령 팔레트(막대가 쉬는 동안)에서는 접근 키를 쓰지 않는다. 그 글자는 검색 칸 같은 문자 경로의 것이다.
  • Alt+글자가 막대 접근 키와 앱 명령에 함께 걸리면 막대가 이긴다. 키 처리기·앱 정책보다 앞서 받기 때문이다. menu_bar_access_conflicts로 미리 찾는다.
  • 항목 hover·눌림과 키보드 강조는 같은 바탕으로 그린다. 하위 메뉴를 연 항목도 강조로 남는다.
  • 자식 있는 항목에 hover_delay 동안 멎으면 연다. 열린 자식이 있으면 잎·비활성 형제 위에 멎었을 때 그 자식을 닫는다. 형제 위를 지나며 움직이면 시계를 다시 센다. 지연 전에 자식 표면에 닿으면 아무것도 내지 않는다.
  • 메뉴 항목이 아닌 요소가 같은 키를 써도 하위 메뉴 시계가 서지 않는다.
  • 막대가 열린 동안 다른 막대 항목에 마우스·펜이 오면 지연 없이 그 메뉴로 옮긴다. 터치에는 없다. 막대 항목 클릭은 닫힌 항목이면 { key, true, false }, 열린 항목이면 {}다.
  • 초점. 메뉴 항목과 막대 항목은 Tab 자리가 아니다. 메뉴를 키보드로 다루는 동안 키보드 초점은 연 자리에 그대로 있다. 그래서 메뉴를 닫은 뒤 "초점을 돌려놓는" 일이 따로 없다.
  • 막대와 막대 항목은 눌러도 글 칸의 초점을 가져가지 않는다(set_preserve_pointer_focus(true)). 그러나 메뉴 popup의 항목을 마우스로 누르면 초점이 지워진다 — 코드에서 확인한 동작이다. 막대 소스의 주석은 "메뉴를 고르고 나면 글을 치던 자리로 돌아가야 한다"고 적지만, 메뉴 항목에는 그 설정이 없다. 콤보의 후보 popup은 모든 부품에 그 설정을 걸어 이것을 피한다.

함정

오류 없이 조용히 틀리는 자리들이다. "코드에서 확인한 동작"은 test가 잠그지 않은 것을 소스로 따라간 결론이다.

  1. 정책의 menu()를 재정의하지 않으면 메뉴가 키보드로 움직이지 않는다. 기본 구현이 std::nullopt다. 메뉴가 떠도 ↑/↓/Enter가 뒤 화면으로 간다.
  2. 고르기가 메뉴를 닫지 않는다. 닫는 것은 앱이다. 잎 항목은 after_select로 닫기 메시지를 함께 낼 수 있고, 막대의 메뉴는 make_menu_bar_popup이 채운다.
  3. Esc의 뜻은 가장 깊은 popup의 dismiss가 먼저 정한다. 표면은 Esc를 controller보다 먼저 가장 깊은 popup의 dismiss(escape_key)에 묻고, 메시지가 나면 키를 삼킨다. 그러면 close_submenu·close_menu()는 불리지 않는다. 하위 메뉴 popup이 Esc에 "전부 닫기"를 내면 Esc 한 번에 메뉴가 다 닫힌다. 한 단계씩 닫으려면 그 popup이 "그 깊이만 닫기"를 내거나 빈 액션을 돌려준다.
  4. "남기기"는 luil::input_action {}이다. luil::app_message {}는 빈 액션이 아니라 메시지 하나로 나간다. 그 popup은 그 frame에 "닫자고 했다"로 표시되어 같은 frame의 다음 계기에 다시 묻지 않고, Esc라면 키가 삼켜진다. examples/tool_window/main.cpp의 미리보기 popup이 남기는 계기에 luil::app_message {}를 돌려준다 — 이 계약에서는 빈 액션이 아니다.
  5. 마우스로 메뉴 항목을 고르면 키보드 초점이 지워진다 (코드에서 확인한 동작). 메뉴 항목은 Tab 자리가 아니고 preserves_pointer_focus()도 거짓이라, 누를 때 controller가 초점을 비운다. 글 칸에서 연 메뉴라면 고른 뒤 caret이 없다. Enter·접근 키로 고르면 초점은 그대로다. 되돌려야 하면 앱이 ui_frame::focus를 싣는다. 이 경우를 잠근 test는 없다.
  6. 메뉴가 열린 동안 앱 단축키는 오지 않는다. 메뉴가 쓰지 않은 키를 controller가 삼킨다. 메뉴 막대가 "선" 동안(열리지 않았어도)도 같다.
  7. shortcut_text는 그림일 뿐이다. 그 단축키를 실행하려면 정책의 on_key에서 match_command 등으로 맞춘다.
  8. check·radio 항목에 icon을 주어도 그리지 않는다. 체크 글리프와 점이 그 자리를 쓴다.
  9. 접근 키는 컨텍스트 메뉴에서 먹지 않는다. 막대에서 연 메뉴(menu_keys)에서만이다. 컨텍스트 메뉴의 글자는 뒤 글 칸·묶음으로 간다.
  10. make_menu_bar_popup은 popup.dismiss와 빈 after_select를 덮어쓴다 (막대에 set_state가 있을 때). 앱이 따로 단 dismiss는 쓰이지 않는다.
  11. menu_popup_config의 corner·font_size·weight가 비면 내장 스타일 값이다. 실행 중 스타일(ui_frame::style)을 바꾼 앱은 그 값을 넘겨야 폭이 맞고 모서리가 같다.
  12. 하위 메뉴 자리는 앱이 센다. 상수 menu_item_height(26)가 아니라 menu_row_height()로 세야 큰 글자에서 어긋나지 않는다. 앞 항목들의 구분선(9)도 더한다.
  13. 자식 메뉴의 짝이 어긋나면 hover 닫힘이 그 자식을 찾지 못한다. depth는 부모 + 1, parent_surface는 부모 popup id, anchor_key는 부모의 opened_key여야 한다.
  14. popup의 x·y는 앵커 표면 기준 논리 픽셀이다. 우클릭 좌표(물리 픽셀)를 배율로 나누지 않으면 고배율에서 메뉴가 엉뚱한 곳에 선다.
  15. 같은 frame에 같은 id의 popup이 둘이면 둘 다 서지 않는다. 빈 id, 크기 0, 창 id와 같은 id도 오류 없이 걸러진다. 모든 host가 같은 순서 함수를 쓴다. 하위 메뉴 popup id를 부모와 겹치지 않게 짓는다.
  16. 필드·막대 포인터는 그 frame이 게시되기 전까지만 유효하다. build에서 남긴 const ui_element*로 같은 frame의 popup 자리만 잰다.
  17. "한 번에 하나만"은 앱이 지킨다. popup 목록이 앱 상태라 라이브러리가 강제하지 못한다.
  18. 메뉴 막대는 대화 상자(초점 가둠)가 떠 있으면 키를 받지 않는다. active_menu_bar가 가둠 밖 막대를 거른다.
  19. Alt+글자 앱 명령은 같은 글자의 막대 접근 키에 진다. menu_bar_access_conflicts로 미리 찾는다.
  20. macOS에는 Alt 단독이 없다 (코드에서 확인한 동작). 막대가 쉬는 동안 Command·Control 없는 글자 키는 입력기로 가므로, Option+글자도 키가 아니라 입력기의 글자가 되어 막대 접근 키에 닿지 않는다. 키보드로 막대를 세우는 길은 F10이 남는다. macOS를 겨냥하면 f10_activates를 끄지 않는다. 실기기에서 돌려 보지는 않았다.

자주 묻는 질문

메뉴가 열려 있는지는 누가 들고 있나?

앱이다. popup을 ui_frame::popups에 싣는 동안만 메뉴가 있다.

메뉴 요소는 고른 키를 메시지로 낼 뿐 아무것도 기억하지 않는다. 고른 뒤 닫는 것, 바깥 누름에 닫는 것 모두 앱이 상태를 지워서 일어난다 (개념).

메뉴를 띄웠는데 ↑/↓가 안 먹는다.

정책의 menu()가 { ui_element_kind::menu, ui_element_kind::menu_item }을 돌려줘야 한다.

기본 구현은 std::nullopt라 메뉴 키보드 탐색이 꺼져 있다. 재정의하면 메뉴 container가 어느 표면에든 서 있는 동안 ↑/↓/Enter/←/→가 메뉴의 것이 된다.

Esc를 눌렀는데 close_menu()가 불리지 않는다.

표면이 Esc를 먼저 popup의 dismiss(escape_key)에 묻고, 메시지가 나면 키를 삼키기 때문이다.

닫기는 dismiss에서 받으면 된다. close_menu()는 어느 popup도 Esc에 메시지를 내지 않았을 때(빈 액션)만 쓰인다 (Esc가 지나는 차례).

Esc 한 번에 하위 메뉴만 닫고 부모는 남기려면?

하위 메뉴 popup의 dismiss가 Esc에 "그 깊이만 닫기" 메시지를 내게 한다.

표면은 가장 깊은 popup에만 Esc를 묻는다. 그 popup이 빈 액션을 돌려줘도 된다 — 그러면 Esc가 controller로 가서 그 메뉴의 close_submenu를 부른다. 데모 셸의 막대 메뉴가 앞의 방식이다 (메뉴 막대).

고른 뒤 메뉴가 저절로 닫히게 하려면?

menu_config::after_select에 닫기 메시지를 준다.

잎 항목을 고르면 select 다음에 함께 나간다. 하위 메뉴를 여는 항목에서는 나가지 않는다. 막대의 메뉴는 make_menu_bar_popup이 비어 있는 after_select를 "막대 쉬기"로 채운다.

구분선은 어떻게 넣나?

구분선 항목은 없다. 아래 항목의 separator_above = true다.

그 항목 위에 9 논리 픽셀(menu_separator_height) 띠가 서고 가운데에 선을 긋는다. 하위 메뉴 자리를 셀 때 이 높이도 더한다.

체크 표시가 있는 메뉴 항목은?

kind = menu_item_kind::check와 checked. 라디오는 menu_item_kind::radio다.

실행 메시지는 그대로 select(key)다. 표시는 앱이 다음 frame의 checked로 바꾼다. 이 두 종류는 icon을 그리지 않는다.

하위 메뉴는 라이브러리가 띄우나?

아니다. 앱이 open_submenu로 경로를 받아 자식 popup을 짓는다.

자식 메뉴에는 depth·parent_surface·anchor_key·close_submenu를, 자식 popup에는 부모 popup id를 anchor로 준다 (하위 메뉴, 여러 단계).

하위 메뉴 popup의 y는 어떻게 구하나?

menu_padding에서 시작해 앞 항목마다 menu_row_height(), 구분선마다 menu_separator_height를 더하고, 거기서 menu_padding을 뺀다.

x는 부모 popup의 폭이다. 화면 오른쪽에 모자라면 Windows·macOS host가 부모 왼쪽으로 뒤집는다.

하위 메뉴가 너무 빨리(늦게) 열린다.

menu_config::hover_delay다. 기본 300ms.

같은 지연이 "잎 형제 위에 멎으면 열린 자식을 닫는" 데도 쓰인다. 형제 위를 지나며 움직이면 시계를 다시 센다.

메뉴에 단축키 글을 넣었는데 눌러도 실행되지 않는다.

shortcut_text는 표시 열이다. 정책의 on_key에서 명령표로 맞춘다.

menu_item_from으로 명령에서 항목을 짓고, 같은 명령표를 match_command로 맞춘다 (명령표). 메뉴가 열린 동안에는 그 키가 오지 않는다.

컨텍스트 메뉴에서 글자로 항목을 고를 수 있나?

없다. 접근 키는 막대에서 연 메뉴에서만 먹는다.

검색이 필요하면 popup에 글 칸을 함께 둔다. 데모의 검색 메뉴가 그렇게 한다 (검색 칸이 있는 목록).

한글 라벨에 접근 키를 어떻게 다나?

access_key = U'f'. 라벨에 F가 없으면 "파일(F)"로 그린다.

접근 이름은 "파일" 그대로이고, 보조 기술에는 "Alt+F"로 따로 읽힌다. 맞추기는 키 이름으로 하므로 한국어 입력기가 켜져 있어도 같은 키가 맞는다.

F10을 내 앱 단축키로 쓰고 싶다.

menu_bar_config::f10_activates = false.

Alt 단독은 그대로 막대를 세운다. 다만 Alt 단독은 Windows host에만 있고 macOS의 쉬는 막대는 Option+글자도 받지 못하므로, macOS에서 F10을 끄면 키보드로 막대를 세울 길이 없어진다 (코드에서 확인한 동작).

Alt+F로 등록한 앱 명령이 막대에 먹힌다.

막대가 이긴다. menu_bar_access_conflicts로 겹침을 찾는다.

막대의 Alt+접근 키는 키 처리기·앱 정책보다 앞서 받는다. Ctrl·Shift가 함께인 단축키나 꺼진 막대 항목은 겹침이 아니다.

키보드나 터치로 컨텍스트 메뉴를 열려면?

우클릭 액션만 달면 된다.

Shift+F10이 같은 액션을 요소 한가운데 좌표로 실행하고, 터치의 길게 누르기(기본 600ms)도 right_click이다 (여는 손).

보조 창 안에서 연 메뉴의 좌표 기준은?

anchor에 그 창 id를 주면 그 창 client 기준 논리 픽셀이다.

배율도 그 창의 것이다. 주 창과 다른 모니터에 있을 수 있으니 그 창의 metrics에서 배율을 꺼낸다 (보조 창).

메뉴를 고른 뒤 글 칸의 caret이 사라졌다.

마우스로 고르면 초점이 지워진다. 코드에서 확인한 동작이다.

메뉴 항목은 Tab 자리가 아니고 누름에 초점을 지키지 않는다. 키보드로 고르면 초점이 남는다. 되돌리려면 ui_frame::focus로 글 칸을 다시 요청한다.

메뉴 막대가 macOS 화면 위 시스템 메뉴 막대에 들어가나?

들어가지 않는다. 창 안에 그린다.

macOS host는 시스템 막대에 앱 메뉴와 편집 메뉴 자리만 세운다.

대화 상자 안에서 메뉴 막대가 Alt에 반응하지 않는다.

초점 가둠 밖의 막대는 키를 받지 않는다.

active_menu_bar가 보이고, 켜져 있고, set_state가 있고, 가둠 안인 막대만 고른다.
