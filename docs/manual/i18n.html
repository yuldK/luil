다국어

luil의 다국어는 빌드 때 짓는 정적 문자열 표와 프로세스 하나의 언어 선호 목록이다. 언어는 앱이 고른다. 라이브러리 기본 문구는 set_text_languages를 따르고, 앱 표는 앱이 같은 목록으로 select_strings를 불러 쥔다. 글은 element를 지을 때 정해지고 다음 frame에 화면이 바뀐다. 정한 적이 없으면 한국어다.

이 문서를 읽으면

  1. 앱의 문자열 표를 짓고 자리 값과 복수형을 채운다.
  2. 설정 화면의 언어 바꿈을 라이브러리 기본 문구와 앱 표에 함께 건다.
  3. OS 표시 언어와 주 첫 요일을 앱이 읽어 넣는다.
  4. 없는 것(숫자·날짜 서식, 오른쪽에서 왼쪽 쓰기)을 알고 피해 간다.

무엇을 어디서 바꾸나

화면 글은 두 표에서 온다. 라이브러리가 스스로 놓는 글과 앱이 놓는 글이다. 둘 다 빌드 때 C++ 헤더가 되고, 언어는 앱이 정한다.

라이브러리 기본 문구

  • element가 스스로 놓는 글이다 — 닫기, 심각도 낱말, 테마 카드, 달력, 편집 메뉴.
  • assets/strings의 표(키 123개)다. 기본 언어는 ko다.
  • 언어는 set_text_languages가 정한다. config 칸에 글을 주면 그 글이다.

앱 문자열 표

  • 앱의 글이다. 언어마다 <태그>.json 파일 하나다.
  • luil_add_string_table이 target에 생성 헤더를 짓는다.
  • 언어는 앱이 select_strings로 고른 string_lookup 값이다.

OS 지역 값

  • user_first_weekday() — 지역 설정의 주 첫 요일.

개념: 언어는 앱이 고르고, 글은 지을 때 정해진다

라이브러리는 OS 언어를 스스로 읽지 않는다. 앱이 정한 목록이 프로세스에 하나 있고, element는 지어질 때 그 목록으로 글을 고른다.

언어를 바꾸는 한 바퀴

앱 (설정 칸)사용자가 언어를 고른다. 칸이 앱 메시지를 낸다. "시스템"이면 앱이 읽어 둔 user_ui_languages() 목록이다.

logic thread같은 목록으로 select_strings(앱 표, 목록)을 불러 앱 상태의 string_lookup을 바꾼다.

UI thread새 tree를 그린다. 이미 지어 둔 element나 캐시한 tree의 글은 그대로다 — 다시 지어야 바뀐다.

언어를 고르는 규칙

  1. 글자 단위로 견준다. _는 -로, A~Z는 소문자로 접는다. 그 밖의 글자는 그대로다.
  2. 선호 태그를 표의 언어와 그대로 견주고, 없으면 끝 부분을 하나 뗀다(zh-Hant-TW → zh-Hant → zh). 떼는 것은 선호 쪽뿐이다.
  3. 한 태그를 다 떼고도 없으면 다음 태그로 간다. 그래서 앞 태그의 뗀 값이 뒤 태그의 정확한 값보다 앞선다.
  4. 아무것도 맞지 않으면 표의 첫 언어(기본 언어)다. 빈 목록·빈 태그도 그렇다.

문장 채우기

  1. 왼쪽부터 읽는다. {{·}}는 글자 {·} 하나다.
  2. 다음에 오는 {·} 가운데 }가 먼저면 그 사이가 이름이다. 인자에 있으면 값을, 없으면 {이름}을 그대로 둔다.
  3. 짝 없는 괄호도 지우지 않는다. 생성기를 거친 표에는 오지 않는 글이다.
  • 자리 값은 {이름}이다. 인자에 없는 이름은 화면에 그대로 남아 개발자가 본다.
  • 인자는 이름과 값(std::u8string_view 글이나 std::int64_t 정수)이다. 같은 이름을 두 번 주면 앞의 것이 쓰인다. 문장이 쓰지 않는 인자는 무시한다.
  • 정수는 std::to_chars로 십진 숫자 글자를 짓는다. 로케일을 읽지 않아 자릿점이 끼지 않고, 음수는 -다. INT64_MIN까지 든다.
  • text(key)는 자리 값을 채우지 않은 문장이다. 복수형 키면 other 꼴이다.

실습: 문자열 표 놀이터

시험 표(tests/strings의 다섯 언어)로 선호 목록에서 언어를 고르고, 고른 언어의 문장에 인자를 넣어 채우고, 수 하나의 복수 범주를 본다.

옮긴 것: 태그 견주기와 끝 떼기(same_language_tag·parent_language_tag), 언어 고르기(select_strings), plural_category_for, string_lookup::text·string_lookup::format과 그 안의 인자 찾기·숫자 짓기·채우기(assets/i18nmodel.js, 원본 src/text/string_table.cpp). 표 자료는 tests/strings를 저장소의 생성기로 지은 test_strings.h를 컴파일한 프로그램이 낸 값이다. 라이브러리 표는 언어 태그(ko·en)만 싣는다. 대조: 이 커밋의 src/text/string_table.cpp와 생성 헤더를 링크한 프로그램의 출력과 선호 목록 4,013개(두 표 모두), 복수 범주 1,230건(int64 끝값 포함), text 45건, format 12,015건(언어 5 × 키 9 × 인자 묶음 267), 생성기를 거치지 않은 깨진 괄호 문장 6,000건이 모두 같다. test가 잠근 기대값 26개도 같다. 걸음 표의 "견준 태그"는 이식이 견준 차례를 적은 것이다 — 원본은 걸음을 내지 않으므로 대조한 것은 최종 답이다. 이 문서의 것: 선호 목록을 쉼표로 가르는 것과 칸의 글을 int64로 읽는 것(int64가 아니면 그 인자를 넘기지 않는다). 옮기지 않은 것: 생성기의 검사(빌드 때 일), set_text_languages의 프로세스 상태, element가 기본 문구로 그리는 그림.

만들기: 앱의 문자열 표

언어 파일을 두고, target을 정의한 CMakeLists에서 함수를 부르고, 생성 헤더를 include한다.

  1. 언어마다 <태그>.json을 둔다. 파일 이름이 언어 태그이고 머리의 language가 같아야 한다.
  2. target을 정의한 CMakeLists에서 luil_add_string_table을 부른다.
  3. 생성 헤더 <NAME>.h를 include해 NAME::key·NAME::table·NAME::text·NAME::format을 쓴다.

1. 언어 파일. 사진 앱의 두 키다. 기본 언어는 ko다.

2. CMake. 함수의 주석이 그 꼴이다. 동영상 예제가 실제로 부르는 자리다.

3. 생성 헤더. 위 두 파일을 저장소의 cmake/generate_strings.cmake에 BASE ko, NAMESPACE app_strings로 넣어 돌린 출력 그대로다. 키는 이름 차례, 언어는 기본 언어 다음 태그 차례다.

4. 쓰기. 앱은 고른 string_lookup을 상태로 쥐고 글을 꺼낸다. 동영상 예제의 화면 값이다.

  • 자리 값은 luil::string_argument { u8"file", file }처럼 이름과 값이다.
  • 설치본에서도 같은 함수다. 설치되는 CMake 파일이 생성기를 함께 싣는다.
  • 생성 헤더는 그 target의 PRIVATE include다. 다른 target이 include하면 보이지 않는다.

만들기: 수에 따라 달라지는 문장

언어 파일 머리에 규칙을 두고, 수가 끼는 문장을 범주 객체로 적고, count라는 정수 인자로 format을 부른다.

시험 표가 가장 짧은 예다. 기본 언어는 en이다.

  • "plural": "one" 언어는 one·other 둘 다, "other" 언어는 other 하나만 적는다. 생성기가 빠지거나 남는 범주를 막는다.
  • 꼴 하나는 자리 값의 일부만 써도 된다(영어 one 꼴 "a file"). 범주 객체는 모든 언어에서 {count}를 받아야 한다.
  • 한 키는 모든 언어에서 꼴이 같다 — 글이거나 범주 객체다.
  • 기본 언어 파일의 arguments는 기본 언어 문장이 쓰지 않는 이름을 밝힌다. 다른 언어 문장은 그 이름도 쓸 수 있다.
  1. ko는 늘 other다. 1도 "파일 1개 선택됨"이다.
  2. 1과 -1이 one, 0·2·백만·INT64 끝값은 other다.
  3. one 꼴 "a file"은 {count}를 쓰지 않는다.
  4. one 꼴을 비워 두면 "1 files found"다.
  5. 글 "1"은 other를 고르고, 인자가 없으면 {count}가 남는다.

만들기: 언어 바꾸기 (설정 화면의 "언어" 칸)

언어 메시지 하나에서 두 표를 같은 목록으로 고른다. "시스템"은 앱이 읽어 둔 OS 목록이다.

앱 표까지 함께 바꾸는 예는 저장소에 없다. 위에서 지은 app_strings로 쓰면 이렇다.

이 코드를 생성 헤더와 함께 src/text/string_table.cpp에 링크해 돌린 출력이다 (selection_text 0·1·2와 save_label).

  • 데스크톱 데모에는 앞으로 올 때의 lifecycle 메시지가 없어 지역 값을 다시 읽지 않는다.

모바일 데모. Activity마다 driver가 새로 서므로, 설 때 text_languages()에서 칸을 되찾고 OS 목록이 바뀌면 "시스템" 칸에서 따라간다.

만들기: OS 언어로 시작하기

시작할 때 OS 목록을 읽어 두 표에 함께 건다. 동영상 예제의 Windows 진입점이다(macOS 진입점도 같은 세 줄이다).

  • Windows는 표시 언어를 바꾸면 다시 로그인해야 한다. 시작할 때 한 번이면 된다.
  • Android는 시스템 언어를 바꾸면 프로세스를 남긴 채 Activity만 다시 세운다. host가 OS 언어를 다시 읽고 앱의 on_started를 다시 부른다. 정한 목록은 프로세스에 남는다.
  • Android의 OS 목록은 태그 하나다(ko-KR 꼴). 그 태그가 표에 없으면(fr-FR) 라이브러리 기본 문구는 한국어다. 영어로 물러서게 하려면 앱이 목록 끝에 u8"en"을 더한다.
  • 지역 질의는 부를 때마다 OS에 묻는다. 모바일 데모는 delegate가 시작할 때와 앞으로 올 때 읽어 메시지로 넣는다.

만들기: 주 첫 요일과 날짜 꼴

달력의 첫 요일은 기본이 일요일이고 앱이 넣는다. 날짜 칸의 표시 글은 라이브러리 표의 문장이고 앱이 함수로 덮는다.

데스크톱 데모의 팝업 페이지다. 셸이 읽은 첫 요일을 메시지로 받아 두고, "OS 첫 요일" 체크를 켜면 달력에 넣는다.

날짜 칸의 표시 글은 비면 라이브러리 표의 문장이다 — ko "{year}년 {month}월 {day}일", en "{month_name} {day}, {year}". 다른 꼴이 필요하면 date_field_config::format에 함수를 준다. 숫자는 앱이 직접 짓는다.

달력이 스스로 놓는 글(이름·이전 달·다음 달·오늘·고를 수 없음·요일 일곱·머리 제목·날 이름)은 calendar_text의 칸마다 비면 기본 문구다.

만들기: 라이브러리 기본 문구를 덮거나 언어를 더하기

글 하나는 config 칸에 준다. 언어 하나를 통째로 더하려면 라이브러리 표의 폴더를 바꾼다.

글 하나만 덮기. 빈 글(empty())일 때만 기본 문구다. 칸마다 따로 판정하고, 공백만 있는 글은 앱의 글이다.

언어 하나를 더하기. LUIL_STRINGS로 라이브러리 표의 폴더를 바꾸고 그 폴더에 ko.json(저장소 것과 키 집합이 같은 것)과 ja.json 같은 언어 파일을 둔다. 기본 언어는 ko이고 생성기가 키 집합을 저장소의 ko.json과 견준다.

  • 언어 파일 사이의 키가 하나라도 어긋나면 빠진 것과 남는 것을 모두 모아 빌드를 세운다.
  • 키 컬러 이름에도 그 언어를 보이려면 카탈로그(LUIL_ACCENT_CATALOG)의 label 맵에 같은 태그를 둔다. accent_label은 라이브러리 표에서 고른 언어로만 찾는다 (테마와 스타일).
  • 이 조리법은 저장소에서 빌드해 보지 않았다. 소비자 폴더로 바꾼 빌드 test가 없다. 생성기가 받고 막는 경우는 test가 친다.

사건과 메시지

라이브러리는 언어 바뀜을 알리는 메시지를 내지 않는다. 언어는 앱이 정하는 값이고, 바꾼 뒤 짓는 element부터 새 언어다.

사건무엇이 오나앱이 할 일
사용자가 설정 칸에서 언어를 고름앱이 정한 메시지 (데모: gallery_choice_intent, device_language_intent)handle에서 set_text_languages와 select_strings. 다음 make_frame이 새 언어로 짓는다
앱이 시작함on_started (데모가 os_locale_intent를 넣는다)user_ui_languages()·user_first_weekday()를 읽어 둔다
앱이 앞으로 옴 (모바일)make_lifecycle_message(app_lifecycle::foreground)지역 값을 다시 읽는다. 지역 설정에서 첫 요일을 바꾸고 돌아온 자리다
OS 표시 언어가 바뀜Windows: 없음(다시 로그인). Android: Activity가 다시 서고 on_started가 다시 불린다. macOS·iOS: 시작할 때 다시 읽는다"시스템"을 고른 상태면 새 목록으로 다시 건다
라이브러리 언어가 바뀜메시지 없음캐시한 tree가 있으면 다시 짓는다. 키 컬러 이름(accent_label)은 다음 frame에 새 언어다

접근성

기본 문구의 대부분은 화면 읽기가 듣는 접근 이름이다. 언어를 정하면 그 글도 함께 바뀐다.

  • 접근 이름이 고른 언어를 따른다. 닫기 단추 이름, 심각도 낱말, 묶음 이름, 달력 날 이름이 모두 기본 문구다. 언어를 정하지 않은 앱은 영어 사용자에게도 한국어 이름을 읽힌다.
  • Win32는 accessibility().name을 UIA Name으로 낸다. Android의 luil에는 접근성 계층이 없어 폰에서 바뀌는 것은 화면 글(줌 단추·테마 카드·날짜 칸·편집 메뉴)뿐이다.
  • 접근 이름 조각(심각도 낱말 + 제목 + 본문)은 공백으로 잇는다. 언어마다 쉼표·쌍점으로 잇는 관례는 따르지 않는다.
  • 번역 글이 한국어보다 길면 각 element의 지금 규칙(말줄임·줄 바꿈)을 따른다. 폭을 글에 맞춰 늘리지 않는다 — 줌 단추는 56 논리 픽셀이 기준이라 데모는 영어 줌 단추 글을 Out·In·Fit으로 줄였다.
  • 색만으로 뜻을 싣지 않는 규칙은 언어와 무관하다 — 심각도는 낱말과 글리프가 함께 말한다 (접근성).
  • 배율·테마·고대비·움직임 줄이기와 입력·초점에는 닿지 않는다.

대체 글꼴(한자 자형)·글자 모양 짓기의 언어GetUserDefaultLocaleName — 지역 서식 이름이라 표시 언어와 다를 수 있다선호 언어macOS와 같다host가 읽어 둔 언어
OS 언어가 바뀌면다시 로그인시작할 때 다시 읽는다시작할 때 다시 읽는다Activity가 다시 설 때
  • 편집 메뉴는 "기본 문구는 OS를 읽지 않는다"의 하나뿐인 예외다. 언어를 정하지 않은 앱의 영어 폰에서는 편집 메뉴만 영어이고 나머지 기본 문구는 한국어다. 앱이 정하면(빈 목록도) 한 언어가 된다. iOS는 링크 두 줄만 이 규칙을 따른다.
  • 대체 글꼴은 OS 언어로 고르므로 앱 언어가 OS와 다르면 한자 자형이 OS 언어를 따른다.
  • OS 쪽 동작은 코드에서 확인한 것이고 그 OS에서 돌려 보지 않았다.

함정

오류 없이 조용히 틀리는 자리들이다.

  1. set_text_languages만 부른다. 라이브러리 기본 문구만 바뀌고 앱 표는 옛 언어다. 같은 목록으로 select_strings를 다시 부른다.
  2. 언어를 바꿨는데 일부 글이 그대로다. 이미 지은 element와 캐시한 tree(한 번 지어 둔 popup tree 따위)의 글은 바뀌지 않는다. 다시 짓는다.
  3. OS를 따를 줄 알았다. 라이브러리 기본 문구는 OS를 읽지 않는다. 기본은 한국어다. 앱이 user_ui_languages()를 읽어 넣는다.
  4. 빈 목록은 "정하지 않음"이 아니다. 빈 목록도 정한 것이고 한국어다. 편집 메뉴도 OS로 물러서지 않는다.
  5. 표에 zh-Hant만 두고 선호가 zh다. 고르지 않는다. 떼는 것은 선호 쪽 태그뿐이라 기본 언어가 나온다. 표에 zh도 둔다.
  6. Android에서 OS 목록을 그대로 넘긴다. 태그가 하나뿐이라 표에 없는 언어(fr-FR)면 한국어다. 물러설 언어를 목록 끝에 더한다.
  7. count를 글로 준다. 복수형이 other로 고정된다. 정수(std::int64_t)로 준다.
  8. 인자 이름을 틀린다. 생성기는 표의 이름만 본다. 실행 중에는 {이름}이 화면에 그대로 남는다.
  9. 자리 값 뒤에 조사를 붙인다("{name}이"). 조사 고르기가 없다. 자리 값 뒤에 조사가 오지 않게 문장을 쓴다.
  10. 수를 1,234나 소수로 보이려 한다. 서식이 없다. 앱이 지은 글을 글 인자로 준다(별점의 "3.5"가 그 꼴).
  11. fr·ru의 복수형. 규칙이 둘뿐이라 맞지 않는다. one으로 어림하거나 수를 문장 밖에 둔다.
  12. 키 컬러 이름에 accent_definition::label을 쓴다. 늘 한국어다. 두 데모의 테마 페이지 제목이 그렇다. accent_label을 쓴다.
  13. 카탈로그 이름에 언어를 더했는데 안 나온다. 라이브러리 표에 그 언어가 없으면 고르지 않는다.
  14. 다른 CMakeLists에서 luil_add_string_table을 부른다. 구성이 선다. target을 정의한 곳에서 부른다.
  15. 키가 delete·default 같은 C++ 예약어다. 빌드가 선다.
  16. 한 파일에 같은 키를 두 번 적었다. 생성기가 잡지 못한다.
  17. 손으로 지은 표가 먼저 사라진다. string_lookup은 포인터만 든다. 생성 헤더의 표는 정적 저장소라 걱정이 없다.
  18. 페이지 코드에서 user_ui_languages()를 부른다. luil_core만 링크하는 test 실행 파일의 링크가 깨진다. 셸이 읽어 메시지로 넣는다.
  19. 오른쪽에서 왼쪽 쓰기. 글자 모양 짓기는 bidi run을 나누지만 문단의 기본 방향은 LTR이고 거울 배치가 없다.

자주 묻는 질문

앱 문구를 영어로 바꾸려면?

앱 표를 짓고, 언어 메시지에서 두 표를 함께 고른다.

set_text_languages와 select_strings에 같은 목록을 준다 (언어 바꾸기).

OS 언어를 따르려면?

시작할 때 user_ui_languages()를 읽어 두 표에 함께 건다.

라이브러리는 스스로 OS를 읽지 않는다 (OS 언어로 시작).

확인·취소·닫기 같은 라이브러리 글이 한국어로 나온다.

기본이 한국어다.

set_text_languages로 언어를 정하거나 그 config 칸에 글을 준다 (기본 문구 칸).

일본어를 더하려면?

앱 표에는 ja.json을 더한다. 키 집합이 같아야 한다.

라이브러리 기본 문구는 LUIL_STRINGS 폴더에 ja.json을, 키 컬러 이름은 카탈로그 label 맵에 ja를 둔다 (라이브러리 기본 문구).

"파일 1개" / "1 file"처럼 수에 따라 문장이 달라야 한다.

범주 객체와 정수 인자 count다.

한국어는 other 하나로 둔다 (복수형).

숫자에 자릿점(1,234)이나 소수를 넣으려면?

서식 기능이 없다.

앱이 글을 지어 글 인자로 준다. 정수 인자는 늘 자릿점 없는 십진 숫자다.

날짜를 2026-11-03으로, 주를 월요일부터 보이려면?

date_field_config::format과 calendar_config::first_day다.

OS의 첫 요일은 user_first_weekday()가 답한다 (첫 요일과 날짜 꼴).

언어를 바꿨는데 일부 글만 그대로다.

이미 지은 element·캐시한 tree, accent_definition::label, 다시 고르지 않은 앱 표 가운데 하나다.

함정을 본다.

번역 파일을 실행 중에 읽거나 바꿀 수 있나?

없다.

빌드 때 C++ 헤더가 된다. 다시 읽기도 없다.

아랍어·히브리어(RTL)를 지원하나?

배치 거울이 없다.

글자 모양 짓기는 bidi run을 나누지만 문단의 기본 방향은 LTR이다. 화면 전환의 쪽은 앱이 밀기의 앞·뒤를 바꿔 넣는다.

en-US·EN-us·zh_hant_tw는 어떻게 맞추나?

대소문자와 _/-를 가리지 않고, 선호 태그의 끝을 하나씩 떼어 찾는다.

시험 표에서 셋은 en·en·zh-Hant를 고른다 (언어를 고르는 규칙).

한 언어 파일에서 키 하나를 빠뜨리면?

빌드가 선다.

빠진 키와 남는 키를 언어·이름으로 한 번에 알린다.

자리 값을 빠뜨리고 format을 부르면?

그 자리는 {이름} 그대로다.

화면에서 보이게 일부러 남긴다.

조사(이/가)를 이름에 맞추려면?

지원하지 않는다.

문장을 자리 값 뒤에 조사가 오지 않게 쓴다.

영어 폰에서 편집 메뉴만 영어다.

앱이 언어를 정하지 않았을 때 모바일 편집 메뉴만 OS 언어(끝에 en)를 따른다.

앱이 정하면 나머지 글과 같은 언어가 된다. iOS는 링크 두 줄만 이 규칙이고 나머지 항목은 시스템 메뉴다 (플랫폼 차이).

라이브러리 기본 문구는 몇 개인가?

라이브러리 표의 키가 123개, 기본 문구 함수가 56개다.

설계 문서의 83개·46개는 그 뒤로 늘기 전의 수다 (라이브러리 표).
